## B. Setup — what is declared before any result

**Network configuration(s).** Four distinct experimental substrates, each declared where it is first used rather than in one place:
1. *Legacy campus prototype* (:261): "a designated class C subnet in our university campus network. The network is divided into 5 subnets, each containing 4 hosts." — 20 hosts. Services: "an _Apache_ Web Server, an _Apache_ FTP server, and an OpenSSH server, each residing on a separate host." MC/MG on "Linux-based (Ubuntu) boxes"; OSPF routers.
2. *SDN / Mininet testbed* (:267): "we implemented it on an OpenFlow controller [28] that manages a Mininet network [29]. We used Mininet to create a network of OpenFlow switches (Open vSwitch kernel switches). Each subnet had a separate network address, and the routing was handled by a controller developed using POX [27]. To generate random networks, we developed a random topology generator for Mininet based on Erdos-Renyi model. This setting allowed us to study effectiveness of RHM for large-scale networks and attack scenarios." — the only stated topology *model* in the paper; no parameters for it (no edge probability, no node count for the generator).
3. *Abstract address-space simulation* for the worm/scanning results: parameters given per-figure, not in a table — m = 2^20, 2^21, 2^22 with m′ = 2^20 scans (Fig. 3, :313); m = 2^20, n = 2^16 (Figs. 7 and 9, :345, :355); n = 2^16 (Fig. 8, :349).
4. *Nmap deprecation experiment* (:381): "The address space is a class _B_ and includes _n_ = 1,000 hosts."
Plus two overhead-only configurations: n = 2^10 hosts (Fig. 11, :403); n′ = 100, ψ = 0.05 (Fig. 12, :421); routers "form a full tree with branching degrees 2, 3, and 4" with 1,000–10,000 hosts (Fig. 13, :423); L = 2^6, N_i = 10, ψ = 0.05 for the SMT table (:441).
How any of these were chosen: **not stated** for any of them.

**Attacker model / scenarios.** The distinctive move: the attacker model is **derived, not stipulated**, via a game whose working is withheld.
- "In order to determine the attacker's optimal scanning strategy, we model the interaction between a scanning attacker and an RHM-enabled network as a static game, where optimality is defined as follows: a scanning strategy is designated as optimal (by the attacker), if for a fixed number of probes it results in discovery of higher number of hosts in the network. This game-theoretic analysis, the details of which are omitted from here for brevity, leads to the following conclusions:" (:277) — followed by two numbered conclusions (:279, :287): the optimal in-interval strategy is "_uniform sampling without replacement_, which is known as cooperative or permutational scanning", and for a static network "cooperative scanning is the most effective scanning strategy, because a static network is analogous to an RHM network with an infinite mutation interval."
- The scenario set is then chosen *against* that derivation: "we theoretically and experimentally evaluate the effectiveness of RHM against well-known non-uniform scanning strategies: (1) cooperative scanning as the optimal scanning technique for static networks, and (2) local-preference, sequential, and divide-and-conquer scannings as non-uniform scanning techniques, which are shown to be more effective than uniform scanning in static networks." (:289) — four scanner classes plus the Nmap reconnaissance case in §VII-E, one subsection each.
- Each scanner class is defined at the head of its own subsection, by citation to the worm literature rather than by construction: sequential — "Blaster is a typical sequential scan worm [26] … it chooses its starting point locally as the first address of its Class C subnetwork with a probability 0.4 [26]" (:341); divide-and-conquer — "if an infected host is scanning subnet _a.b.c.d/k_ and _k < l_, this host would divide its scanning space into halves after it compromises a host; otherwise, _k_ = _l_ …" [31] (:353); cooperative — "a group of _k_ ≥ 1 scanners are cooperatively (_i.e._, in a non-repeating fashion) probing the address range of our network with _m_ addresses and _n_ moving hosts" (:305).
- **Explicit scoping restriction with a cited justification:** "In our analysis, we focus on scanners/worms with low scanning rates, since fast scanning is easy to detect [4]." (:289). And a scenario dropped by appeal to prior work: "Zou _et al._ [26] show that for a sequential scanning worm, using local-preference in selecting the starting point slows down the worm's propagation speed. For this reason, we only analyze a sequential scan worm with a uniformly-chosen starting point." (:343).
- The attacker is also modelled *as a propagating population*, not just a prober: "in case of a cooperative worm each newly infected machine starts acting as a scanner. To analyze the effect of uniform mutation on cooperative worms, we use mathematical propagation modeling [30]. Assume _S(t)_ and _I(t)_ represent the susceptible and infected populations at time _t_" (:315), with RHM adding "_Q(t)_ … the quarantined population at time _t_; _i.e._, susceptible hosts that are not accessible to scanners as a result of mutation" (:317). An SIR-style epidemic model with a defence-induced quarantine compartment.
- A **second, adversarial attacker** is defined only to attack the defence's own detector: "Such adaptability may allow an adversary to evacuate network hosts from certain network ranges … assume the adversary intends to exclude at least _half_ (_M/_2) of ranges from mutation space." (:195). See §D.

**Defence conditions.** Three, and they are named in the preamble before any result: static (baseline), **uniform mutation**, and **adaptive mutation**. "When the non-repetition and non-uniformity hypotheses fail, the mutation is performed uniformly. So, in our evaluation we investigate the effect of both uniform and adaptive mutation on intended threat models. This also allows us to compare uniform versus adaptive mutations in terms of effectiveness." (:291). The "uniform" arm is thus an **ablation of the paper's own contribution** (RHM minus adaptivity), not a competitor technique — the defence axis is internal.
- No-defence baseline: yes, and it is load-bearing in a way most papers' baselines are not — see the metric definitions below. In the surviving figure legends the series are "static", "unif." and "RHM" (:322).
- Comparison to *external* prior defences is by argument and cited numbers, never by re-implementation: "while a DHCP-based randomization can only mutate a host address every 10 − 15 minutes [2], RHM can achieve a mutation rate of 10 seconds" (:377).
- Scheduler: two-level (LFM interval T_LFM, a system parameter; HFM interval T_HFM^i, a per-host parameter) (:89, :91). Mutation intervals are stochastic: "the series of mutation interval lengths for each host generates a Poisson arrival process with mean 1/θ" (:381) — the only distributional statement made about the defence's timing.

**Metrics — defined before any result, as ratios against the static baseline.** This is the paper's signature convention. Both are bold-italic-defined in the §VII preamble:
- "_Deterrence:_ … To quantify deterrence magnitude, we compare attack completion duration in an RHM versus a static network with same configurations. Assume _T_RHM_ and _T_static_ denote the attack completion duration in RHM and a static networks respectively. The _deterrence ratio_ is defined as _T_RHM_/_T_static_ and shows the magnitude of the delay that is incurred on the attack before its completion." (:273)
- "_Detectability:_ … Specifically, assume _C_RHM_ and _C_static_ denote the number of scans generated by attacker in RHM and a static network respectively. The _detectability ratio_ is defined as _C_RHM_/_C_static_." (:275)
- A third, defined at its point of use in §VII-E: "The deprecation ratio is defined as the proportion of addresses that are no longer active, as compared to a ground truth (preliminary reconnaissance)." (:381).
Because every headline metric is a ratio to the static case, the baseline is not a plotted line to be compared against — it is the *denominator*, and "1.0" is the no-effect reading.

**Parameter table.** **No experiment parameter table.** Table I is "DESCRIPTION OF NOTATIONS" (:101–103) — symbol definitions, not values. Table II is "RUNNING TIME OF THE SMT SOLVER" (:435) — a result. Concrete parameter values are scattered through prose at their point of first use: ξ = 2.0 ("In our experiments, we assume that _ξ_ = 2.0", :193); τ = 2 (:221); β ≥ 0.05 (:187); ψ = 0.05 (:421, :441) and ψ ∈ {0.1, 0.25} (:403); L = 2^6 (:441); N_i = 10 (:441), N_i ∈ {3, 120} (:403); ω and α left unset ("Selecting values for _ω_ and _α_ depends on the size of mutation space", :137). Distributions declared: weighted uniform sampling for eIP selection (:161); Poisson arrivals for mutation intervals (:381); Erdős–Rényi for topology generation (:267).

**Replications.** **Stated exactly once in the whole paper, and for an overhead result, not a security result:** "All values have been achieved in real scenarios and averaged over 10 runs." (:447, DNS query counts, Fig. 14). No replication count, seed, or run length is given for any scanning experiment, any worm-propagation experiment, the Fig. 3 mutation-success experiment, or the Nmap deprecation experiment. Horizons appear only as figure x-axes: worm propagation to 1000 sec (:322); "We scanned the whole address space every 2 minutes and over 20 minutes using Nmap [33]" (:381) — i.e. 10 scans.

**Statistics.** No means-with-dispersion, no confidence intervals, no error bars, no significance tests are reported **on any result**. The statistical machinery in the paper (Pearson's χ², a variation of Chauvenet's criterion, coefficient of variation, one-tailed null hypotheses at β ≥ 0.05) is entirely **inside the defence mechanism** — it is how RHM characterises the attacker at runtime (:177–221), not how the authors analyse their own data. This inversion is worth naming: a reader could mistake §III-C for a statistics-of-evaluation section; it is not.

**Other declarations.** Hardware, for one result only: "We use the Z3 SMT solver [6] for our evaluation on a Quad Core processor (3.3GHz, 6M cache) and 8 GB DDR3 RAM." (:427). Tools named with citations: Mininet [29], POX [27], an OpenFlow controller [28], Nmap [33], Z3 [6]. Code/data availability: not stated. Versions: not stated for any tool.

## C. Results — how the numbers are shown

**Order.** Threat-model-major. §VII runs one subsection per scanner class in ascending order of address-sampling *skew* — cooperative (uniform, non-repeating) → local-preference → sequential → divide-and-conquer → real-tool reconnaissance. Within a subsection the pattern is: theory first, then experiment, then the adaptive-vs-uniform comparison. §VII-A states this ordering rule explicitly: "in the following sections we first theoretically investigate the effect of uniform mutation on this worm class, and then extend our analysis to adaptive mutation" (:301). §VIII then runs one subsection per cost axis. Security results never share a figure with cost results.

**Tables.** Two, neither reporting a security result. Table I "DESCRIPTION OF NOTATIONS" (:101). Table II "RUNNING TIME OF THE SMT SOLVER" (:435) — a feasibility table whose distinguishing feature is that **it reports failures as cells**: "In the table, 'UNSAT' means the SMT solver reported that the instance is unsatisfiable. Moreover, 'FAIL' means the SMT solver failed to solve the instance. This means that the upper bound used in the constraint is beyond the solving ability of the SMT solver. In both cases one must relax some of the parameters (such as decreasing the routing table size upper bound, _Λ_, or increasing the number of unused address ranges, _M_) to get a feasible solution." (:441). Reporting the infeasible region, and telling the operator how to escape it, is a convention worth naming.

**How the baseline appears.** Three ways, all of them structural rather than a plotted comparator: (i) as the **denominator** of both headline metrics (:273, :275), so every reported number already encodes the comparison; (ii) as the "static" **series** in propagation figures (:322, and prose at :345, :355); (iii) as a stated **limiting case** of the paper's own model — "a static network is analogous to an RHM network with an infinite mutation interval" (:287), which is what licenses using one attacker-optimality argument for both.

**Comparison phrasing.**
- Range magnitude rather than a point: "note that the mutation can save from 40% to 80% of network hosts from infection" (:313).
- Asymptotic/limit statements, used in place of numbers: "when _Γ_ ≪ _m′_, the mutation success probability remains close to _e^(−m′/m)_. However, as _Γ_ approaches _m′_, the mutation success probability drops to 1 − _m′/m_. In fact, when _m′_ = _m_ = _Γ_ the mutation success probability becomes 0." (:313); "if scanners only scan half of the address space, then _e^(−1/2)_ of hosts will be missed" (:295).
- Hedged ordering, without numbers: "compared to static networks, propagation of sequential worm in the uniform network is **slightly** slower. However, the adaptive technique is **much more effective** than naive uniform mutation, even for higher scanning rates." (:345); "the adaptive mutation of RHM slows down the propagation **more significantly**" (:365); "RHM can **severely** slow down the propagation of sequential worms" (:349). Adverbs carry the comparison; the figures are not read out numerically.
- Monotonicity claims: "larger address space sizes increase deterrence and detectability … higher local scan probabilities results in higher deterrence and detectability" (:337); "the higher the average mutation rate _θ_, the faster the deprecation rate of the information" (:381); "for a fixed LFM interval, the longer HFM intervals results in smaller routing table sizes … for a fixed HFM interval, longer LFM intervals result in larger routing table sizes" (:421) — each with a mechanism clause attached ("because …").
- Named-value overhead readings: "when _N_i_ = 120 and _ψ_ = 0.1 we almost need a large address space of size 2^20. However, when _N_i_ = 3 and _ψ_ = 0.25, the same number of hosts need a much smaller address space of size 2^16." (:403); "the convergence time for branching degree 2 and a network including 10,000 hosts is less than 2 minutes." (:423); "the delay was negligible (less than 5 seconds)" (:265).
- **Claims stated without supporting figures, flagged as such — twice:** "Although not shown here, RHM effectiveness against local-preference sequential worm is even higher than the uniform one." (:343); "Although not shown here, the detectability ratio of RHM against sequential worms is close to 2 regardless of the network size." (:349). Recorded, not judged: the phrase "Although not shown here" is the paper's own marker for an unevidenced result.
- Trade-off framing, stated as such: "This clearly represents the trade-off between benefit that is achieved as a result of faster mutations, and the cost of handling a larger number of DNS queries." (:447).

## D. Narrative — the claims, in order

§VII (security):
1. A rational attacker facing RHM is *forced* into uniform scanning, which is itself detectable: "deployment of RHM in a network will force a rational attacker to commit to uniform scanning, which is highly susceptible to detection [4]." (:289). The evaluation's premise, established before any measurement.
2. Against cooperative scanning, uniform mutation alone suffices: "Even without adaptive mutation, uniform mutation is able to thwart the propagation of cooperative worms." (:301).
3. Theory and experiment agree on mutation success probability: "We can see that the experimental result is roughly consistent with the theoretical analysis." (:313) — plus the 40–80% saved-hosts range and the two asymptotic regimes.
4. (Local-preference, §VII-B — mostly lost in the md.) The surviving claim inverts the static-network intuition: "This shows that contrary to static networks, the more a worm diverges from uniform distribution, the more susceptible it is to adaptive mutation." (:337).
5. Sequential: uniform mutation helps only slightly; adaptive helps a lot, **with a mechanism**: "This is because the probes generated by sequential scanners are highly skewed toward certain ranges of the network (even more than local-preference), allowing our approach to quickly verify the non-uniformity hypothesis and evacuate network hosts from those ranges." (:347).
6. Sequential detectability gain is small, **and the paper explains why against its own interest**: "The low increase in detectability is due to the fact that even in static networks, the sequential scanning strategy generates too many spurious scans." (:349).
7. Divide-and-conquer: static propagates fast "because of the locality of host addresses"; uniform mutation slows it "by uniformly distributing the hosts in the address space"; adaptive slows it more (:355, :365); and the skew-monotonicity claim is repeated: "for larger _l_ values the worm address sampling diverges from uniform distribution more significantly, thus making it more susceptible to adaptive mutation." (:367).
8. Reconnaissance: deprecation rises with mutation rate, gradually rather than in a step, "because … the series of mutation interval lengths for each host generates a Poisson arrival process with mean 1/θ" (:381).
9. Speed and unpredictability as the two differentiators from prior work (:377, :383).

§VIII (cost): address space required grows with mutation rate and falls with tolerated repetition (:403); SMT optimisation "decreases the routing table size significantly" (:421); OSPF convergence < 2 min at 10,000 hosts (:423); SMT solve time is "very sensitive to the number of variables as well as the selection of the upper bound _Λ_" with UNSAT/FAIL regions (:441); DNS load rises with mutation rate (:447); packet-processing delay "negligible" and "increases linearly with the number of packets" (:451).

**Claims about the ATTACKER's properties from the data.** Yes — more than most, and in three distinct modes:
1. *Derived from a model, not from data*: the optimal-strategy result (:279, :287) and the forced-uniform-scanning corollary (:289). The data are never used to check it.
2. *Inferred from the defence's own runtime statistics*: the whole of §III-C is an attacker-characterisation apparatus — the non-uniformity test (χ² against uniform over ranges, :181–187) and the non-repetition test (coefficient of variation on per-address probe counts, :209–215) classify the live attacker's sampling behaviour. The classifications feed the defence, and their *evaluation* is only indirect (adaptive-vs-uniform performance differences).
3. *An analytic bound on the attacker's ability to game the defence's inference* — the paper's most distinctive analysis, and it is an attacker-effort result: "the adversary has to generate M/2·π₂ + M³/6 scans in order to exclude half of ranges from mutation space. This value is significantly high, even for small networks. For example, for _π_2 = 64 and _M_ = 2^10, the adversary has to generate almost 180 million failed scans. For excluding _M_ − 1 ranges from mutation space, he has to generate almost _M_^4/6 failed scans, which for the aforementioned example adds up to almost 183 billion scans! Therefore, manipulation of RHM non-uniformity test requires an impractically high number of failed scans." (:199–207). The companion guard for the second test is a flat rule rather than a bound: "to prevent adversaries from manipulating non-repetition test for concentrating network hosts in certain addresses, RHM never excludes more than _one third_ of network addresses." (:221).
4. External attacker-behaviour constants are imported by citation, not measured: Blaster's 0.4 local-start probability [26] (:341); NASR's 10–15 minute DHCP rate [2] (:377); "fast scanning is easy to detect [4]" (:289).

## E. How theory, simulation and testbed are reconciled

Four evidence types are used, and the paper states the mix up front — "comprehensive evaluation were conducted to study its effectiveness and limitations, using statistical analysis, mathematical propagation modeling, and simulation" (:51), and "using a multitude of theories and techniques" (:465).
- **Closed-form miss-probability analysis** (:293–313) for cooperative scanning, in the *m*, *m′*, Γ variables.
- **Epidemic propagation modelling** (S/I/Q compartments, :315–317) for worms, which the closed-form analysis cannot cover because "each newly infected machine starts acting as a scanner" (:315).
- **Simulation** for the propagation and deterrence/detectability figures (Figs. 5–9).
- **Testbed measurement** for feasibility, reconnaissance deprecation (Nmap on the SDN implementation, :381), routing/DNS/delay overhead, and the legacy prototype (:261–265).
- **The reconciliation is one figure and one sentence.** Fig. 3 plots theoretical and experimental curves for three address-space sizes together, and the verdict is "We can see that the experimental result is roughly consistent with the theoretical analysis." (:313). "Roughly consistent" is the whole agreement claim: no residual, no error bound, no goodness-of-fit — despite the paper's own extensive use of goodness-of-fit machinery elsewhere. No other result is cross-validated across evidence types.
- Division of labour is stated per case rather than globally: the divide-and-conquer subsection reuses the cooperative analysis conditionally — "We assume that each scanner probes its designated address space uniformly. However, if such probing is done non-repeatedly, the analysis for cooperative scanners is also applicable here." (:355).

## F. Sensitivity / parameter analysis

Present but **not sectioned as such** — it is distributed, and split by purpose between §VII (security parameters) and §VIII (deployment parameters).

- **Security-side sweeps.** Scanning-to-mutation rate ratio Γ = η/θ, swept over log₂Γ ∈ [0, 20] (Fig. 3) — the paper's central dimensionless parameter, defined at :309: "We define _Γ_ = _η/θ_ as the ratio of attacker scanning rate on defender mutation rate." Address space m ∈ {2^20, 2^21, 2^22} as a series, not an axis (Fig. 3). Attacker/defender rate pairs (η = 1, θ = 1) vs (η = 5, θ = 0.2) as series (:322). Local-scan probability (Fig. 6, claim at :337). Divide-and-conquer's l parameter (claim at :367). Average mutation rate θ (Fig. 10).
- **Cost-side sweeps.** Mutation rate × repetition probability ψ ∈ {0.1, 0.25} with N_i ∈ {3, 120} (Fig. 11); LFM × HFM interval lengths — a genuine **two-factor** sweep, the only one in the paper (Fig. 12); network size 1,000–10,000 × router branching degree {2, 3, 4} — the second two-factor sweep (Fig. 13); M × n × Λ for SMT solve time (Table II); mutation rate for DNS load (Fig. 14).
- **Design:** one-at-a-time with a second factor as series; never a full factorial, never a reported cell count.
- **Range justification:** not stated for any range. The nearest thing is a *derived requirement* reported as a result: "In Section VII, we show that to provide fast and unpredictable mutation, each network host requires a mutation space of 2^5 - 2^6 available addresses." (:77) — a forward reference from the methodology to the evaluation, so a design constant is justified by a later measurement.
- **Placement:** inside §VII and §VIII as the results themselves. No appendix.
- **Claim supported:** on the security side, that RHM's benefit is governed by the *ratio* of attacker to defender rates rather than by either absolute rate; on the cost side, that the parameters admit an operationally feasible region (and, via Table II, that they also admit an infeasible one).

## G. Discussion / limitations

**No discussion section.** Interpretation is inline, one or two sentences after each figure reference. The conclusion (§IX, :461–473) is pure summary and contains no limitation, no threat to validity and no future work beyond a single forward-looking clause inside §VIII-F.

**Limitations are a subsection of the *overhead* section — §VIII-F (:453–459) — three paragraphs, reproduced verbatim in full:**

> "RHM provides no mitigation against threat models where the adversary knows the domain name of the target host, because the adversary can simply query the DNS to discover the new eIP of the host. Moreover, if a host has a unique fingerprint (operating system, set of services, etc.), it can be distinguished via fingerprinting tools such as Nmap. Shorter mutation intervals would complicate this process by constantly deprecating adversary's information. In addition, we are planning to extend our work to include fingerprint mutation in order to thwart these attack models." (:455)

> "IP mutation can not be deployed for hosts where the IP address is the primary identifier (_e.g._, an unnamed printer or server), or where the correct functionality of hosts' services depends on the end-parties' agreement on the destination's IP address. In these cases, the rIP-based communication protocol could be used (viz. Section IV-B)." (:457)

> "Also, if the address space does not include enough IP addresses (especially in the public address space), RHM may not be able to provide mutation for every host. Also, the mutation is costly (translation, route advertisement, etc.) and it may not be possible to provide it for all network hosts. In these cases, the more critical a host is, the higher priority it should have to be included in mutation." (:459)

Note the pattern: **each limitation is stated and then immediately paired with a mitigation or a deployment rule** ("Shorter mutation intervals would complicate this process"; "the rIP-based communication protocol could be used"; "the more critical a host is, the higher priority it should have"). None is left standing as an unqualified weakness. The abstract pre-announces this section — "We also address limitations of our approach in terms of effectiveness and applicability." (:9) — so limitation coverage is claimed as a contribution.

Other limitation-adjacent statements scattered elsewhere, verbatim:
- "it is practically impossible to sample each eIP from all unused ranges at once, because each unused address range can only be routed to one physical subnet at any given time. Therefore, maximizing unpredictability is not practically possible." (:41) — a bound on the mechanism's own ideal.
- "These weighted mutations may increase divergence from uniform distribution and may reduce unpredictability. Therefore, range-to-host assignments must be scheduled in part based on the trade-off between adaptability and unpredictability." (:43) — the adaptivity/unpredictability tension, conceded in the introduction.
- "Note that the _α_k_ values can not be theoretically calculated, since it depends on the network graph. However, Monte Carlo approaches [34] could be used to derive an approximated average for a specific network." (:409) — an analytic limit conceded, with the empirical escape named.
- "Selecting values for _ω_ and _α_ depends on the size of mutation space. While lower values of _ω_ and higher values of _α_ enable us to achieve more unpredictability in shorter intervals, it may result in exclusion of too many ranges and make the assignment unsatisfiable." (:137) — two parameters left unspecified for the experiments.
- "For scalability, this architecture … could be extended to include several controllers … This can have negative effect on unpredictability, but substantially improves scalability." (:235).

**Absent:** any threat-to-validity discussion of the evaluation itself — nothing on the 20-host prototype's size, the unstated Erdős–Rényi parameters, the missing replication counts, the absence of dispersion, the two "not shown here" claims, or the withheld game-theoretic derivation.

**Replication statement:** none. No code or data release; no seeds; one averaged-over-10-runs statement for one overhead figure (:447). Tools are named and cited (Mininet, POX, OpenFlow, Nmap, Z3) but not versioned.

## H. Transferable vs purpose-specific

**Transfers to an honours dissertation evaluating existing MTD mechanisms against a new attacker model on a simulator:**
- **Defining the headline metrics as ratios against the no-defence run, in the evaluation preamble, before any result** (:273, :275). Deterrence ratio = T_defended/T_static and detectability ratio = C_defended/C_static make every reported number self-comparing, put the null result at exactly 1.0, and remove the need to re-plot the baseline in every figure. Directly portable to an MTTC-style metric.
- **A dimensionless attacker-to-defender rate ratio as the primary x-axis** (Γ = η/θ, :309) instead of absolute mutation periods. It makes the results independent of the simulator's time unit — the single most portable idea in the paper.
- **One subsection per attacker class, each class defined by citation to the behaviour literature rather than invented** (:341, :353) — including citing the empirical constant that defines it (Blaster's 0.4 local-start probability, :341).
- **Ordering the attacker classes along an axis that the defence's mechanism is sensitive to** (here, divergence from uniform sampling), so the results section builds a monotone story rather than a list (:289 → :337 → :347 → :367).
- **Ablating the defence rather than only comparing to no-defence**: uniform mutation vs adaptive mutation isolates the contribution of the adaptive component (:291). The equivalent for a dissertation is running each MTD mechanism alone and in combination against the same attacker.
- **Scoping the attacker explicitly, with a citation for why the excluded region does not matter**: "we focus on scanners/worms with low scanning rates, since fast scanning is easy to detect [4]" (:289). Also dropping a scenario by appeal to prior work rather than silently (:343).
- **Attaching a mechanism clause to every comparative claim** ("This is because the probes generated by sequential scanners are highly skewed …", :347; "because of the locality of host addresses", :355). The claim is never left as a bare direction.
- **Stating a result that runs against the paper's interest, with its explanation** (:349, the small detectability gain against sequential scanners).
- **Reporting the infeasible region as data** (Table II's UNSAT/FAIL cells and the instruction on which parameter to relax, :441) rather than reporting only the cells that worked.
- **Separating security results from cost results into two sections**, and giving cost its own per-axis subsections (§VIII-A…E) — a clean template when a mechanism has several distinct overheads.
- Naming a limitation and pairing it with the deployment rule it implies (:455–459).
- Marking unevidenced claims in the text itself ("Although not shown here", :343, :349) — the habit is right even where the practice is weak; a dissertation should either show it or not claim it.

**Purpose-specific / artefacts of this paper's aim and venue:**
- The SMT/BDD range-assignment formalisation (:81–157) and its solver-runtime evaluation (Table II) — the contribution is a deployable mechanism; a simulator-side dissertation inherits none of this.
- Four evidence types (closed form, epidemic model, simulation, two testbeds) with reconciliation by one sentence on one figure (:313). The *breadth* is a TIFS-journal expectation; the *thinness of the reconciliation* is not a convention to import.
- Worm-propagation curves (S/I/Q over time) as the primary result shape — appropriate because the threat model is self-propagating malware; an APT/lateral-movement attacker needs a different result shape.
- Real-tool measurement (Nmap sweeps every 2 minutes for 20 minutes on a live SDN, :381) as the reconnaissance result — needs an implementation, not a simulator.
- Withholding the attacker-optimality derivation "for brevity" (:277) while relying on it to justify the whole scenario selection — a page-limit compromise that a dissertation has no reason to make, and every reason to reverse.
- No replication count, no dispersion, no seeds on any security result — do not import. The one "averaged over 10 runs" (:447) sets the paper's own floor, and it is applied to the least security-critical figure.
- Statistical hypothesis testing appearing *inside the defence* rather than in the analysis (:181–221) — distinctive here, and a reason not to read this paper as a model for how to analyse simulation output.
- Parameter values scattered at their point of first use with no table — workable across a 16-page journal article with a notation table; not workable for a reproducible simulation study.
