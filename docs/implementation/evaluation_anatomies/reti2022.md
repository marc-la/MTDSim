# reti2022 — evaluation-section anatomy

Source read: /home/marc/GitHub/MTDSim/docs/sources/tactic_profiles/step_d/10_disc/3560828.3564006.md (423 lines; clean md conversion, figures present only as garbled "picture text" blocks with intact captions). Locators are md line numbers, cited as `3560828.3564006.md:<line>`.

Paper's own research question / purpose: present "a methodology to evaluate the effectiveness of honeypots and moving target defense in a network" via simulation, "allowing to make recommendations on how many honeypots to deploy and on how quickly network addresses have to be mutated to effectively disrupt an attack in multiple network and attacker configurations" (3560828.3564006.md:29). Quantification is "by defining three attack strategies and for each strategy it is measured how likely it is for an attacker to successfully exploit a vulnerable host, when the different deception setting are in place" (3560828.3564006.md:33).

## B. Setup — what is declared before any result

**Network configuration(s).**
- Generated by "a modified version of the random scenario generator from NASim" (:167); "three different scenarios, based on different seed, were generated" (:165), seeds 1234, 42, 24121997 (Table 1, :185).
- Fixed: "The network included 256 addresses and two subnets, one only for the attacker. Since the focus was not layed on the firewall, no restrictions were included." (:171). Table 2: addresses 256, subnets 2 (:229–230).
- Varied network size: "Number of normal hosts" 10, 50 (Table 1, :183).
- Sensitive hosts: 3 (:190; Table 2 :212). "for each scenario ten possible services, processes, exploits, privilege escalations and vulnerabilities were given. The number of Operating Systems was set to one and credentials have not been considered." (:190).
- "'Empty' hosts" introduced as undetectable, unattackable addresses to enlarge the mutation address space (:161).
- Topology beyond "two subnets, one only for the attacker": not stated. How the two host sizes were chosen: not stated.

**Attacker model / scenarios.**
- Three agents, each named in single quotes on first definition (not bold): 'careful' (:103), 'standard' (:119), 'aggressive' (:129). "Three attacker agents with different assumptions on their behaviour have been defined and implemented. Each agent had a different tactic to attack the network. This tactic is implemented through fixed behaviour rules. The rules are separated into different phases. Parts of the decisions are chosen randomly." (:85).
- Action alphabet enumerated (:89–101): subnet scan, service scan, OS scan, vulnerability scan, process scan, exploit/privilege escalation, wiretapping.
- Each agent defined as a numbered phase list (careful :105–117; standard :121–127; aggressive :131–137). The MTD-reaction rule is inside the agent definition: careful "If Moving Target Defense is turned on, the agent will start with phase one" (:117); standard "If Moving Target Defense is detected, the agent will start again from phase one" (:127); aggressive has no MTD clause.
- Realism claims attached to agents: standard "the design aimed toward a more realistic approach" (:119); aggressive "could be the behavior of a computer worm" (:129).
- Rationale for fixed-rule agents over RL: "These agents have a clearer behaviour, which makes the comparison more comprehensibly." (:145); "it was chosen to define the attackers with strict strategies to have more comparable and explainable results" (:310–324).
- Attacker goal: "gain root access to all sensitive hosts" (:149), plus the added one-goal variant (:157).

**Defence conditions.**
- Honeypots: "based on the implementation of sensitive hosts. If an agent exploits one honeypot host with either user or root privileges, the goal failed and the agent has lost." (:155). Counts 0, 2, 4, 6, 9, 10 (Table 1, :182). Note the level set is irregular (9 and 10 both; no 8) although prose later says "Employing 8 honeypots" (:264).
- MTD: "After a chosen time, hosts in the same subnet will randomly change their addresses. The time is defined by the actions taken and their associated costs. After this change, the agent does not know which hosts were already exploited." (:159). Movement time None, 25, 50, 75, 100 (Table 1, :183).
- No-defence baseline: yes — honeypots = 0 and movement time = None are levels of the grid; prose refers to "the reference of having no MTD in place" (:268) and Figure 3d "no deception measures" (:281).
- Scheduler: single periodic (time-triggered by action cost) scheme; no alternative strategies.

**Parameter table.** Yes, two. Table 1 "All Possible Varied Parameter Values" (:189), columns Parameter | Description | Value, six rows (honeypots, movement time, hosts, objective, seed, agents) (:179–188). Table 2 "All Fixed Parameter Values" (:232), same columns, 19 rows including rewards, costs (=1), exploit_probs 1.0, privesc_probs 1.0, step_limit 3000, addresses 256, subnets 2 (:210–232). Distributions: only "uniform — Uniform distribution of hosts — True" (:225); no stochastic-parameter distributions otherwise. Exploit success probability fixed at 1.0 (:223–224).

**Replications.** "Each combination of parameters was run 100 times to compensate for randomness in the scenarios and agent behaviours." (:200). Horizon: step_limit 3000 "Maximum number of actions permitted" (:228). Termination rule stated as a three-item list: agent wins (all necessary sensitive hosts exploited, per one_goal), agent loses (exploited a honeypot), agent takes too long (step_limit) (:192–198). Total cell count not stated; from Table 1 it is 6×5×2×2×3×3 = 1080 combinations × 100 runs (my arithmetic, not the paper's).

**Statistics.** Reported quantity is "winning probability" (fraction of runs won) and "number of steps" as box plots (median, quartiles, maximum) (:246). No std, CI, or significance tests stated. Averaging over seeds/hosts/goals when plotting a subset is not stated (e.g. Figure 2 is "for the three agents" with no statement of what is marginalised).

**Other declarations.** Implementation: NASim (Python, OpenAI Gym) with the RL functionality unused (:145); built on "an already expanded version of NASim" with vulnerabilities, vulnerability scan, credentials and wiretapping (:151). Hardware: not stated. Versions: not stated. Code availability: not stated.

## C. Results — how the numbers are shown

**Order.** Declared explicitly: "the results from our experiments are presented from three different perspectives, starting with a comparison of the different attacker types, followed by the impact of honeypots and lastly the impact of moving target defense is considered" (:204). So the order is attacker-first (§6.1), then one defence axis each (§6.2 honeypots, §6.3 MTD). Within §6.2 and §6.3 the pattern is: the single "standard" agent × the defence parameter, then split by network size (a-panels), then split by objective (b-panels).

**Figures (evaluation portion).**
- Figure 1 (:254): 3D bar/point chart; x = number of honeypots (0–10), series = IP changing time (–, 25, 50, 75, 100), z = agent type (s, a, c), y = winning probability. Caption: "Winning probability for different IP changing times of the standard agent (s), aggressive agent (a) and careful agent (c) over an increasing number of honeypots (z-axis)".
- Figure 2 (:263): two panels; (a) x = num honeypots, (b) x = movement time (25, 50, 75, 100, –); y = probability; series = aggressive/standard/careful. Caption: "Comparison of the winning probability for the three agents for a) an increasing number of honeypots and b) an increasing IP changing interval."
- Figure 3 (:282): four box-plot panels of steps by agent: (a) MTD and Honeypots, (b) Honeypots only, (c) MTD only, (d) no deception measures. y-scale 0–3000 for a/c and 0–1200 for b/d (picture text :279).
- Figure 4 (:303): x = number of honeypots, y = winning probability, series = movement time (–, 25, 50, 75, 100), standard agent only. Caption: "Comparison of the probabilities for the standard agent to win for an increasing number of honeypots. The colors represent different movement times".
- Figure 5 (:322): two panels, standard agent; (a) x = honeypots, series = num hosts 10/50 (:316); (b) x = honeypots, series = one goal False/True (:321).
- Figure 6 (:343): two panels, standard agent; (a) x = mutation interval (25, 50, 75, 100, –), series = num hosts 10/50 (:337); (b) x = mutation interval, series = one goal False/True (:340).
- All result figures are of the same family: winning probability vs a defence parameter, one series per second factor. No time-series, no per-run traces.

**Tables in results.** None with results. Table 2 is physically inside §6.1 (:210–232) but is a parameter table.

**Baseline appearance.** As the "–"/None level on the x-axis or in the series legend (Figures 1, 2b, 4, 6) and as honeypots = 0 on the x-axis (Figures 2a, 4, 5); as a separate panel "d) no deception measures" in Figure 3 (:281). Prose uses "reference": "very close to the reference of having no MTD in place" (:268); "For reference, when neither honeypots nor MTD is enabled, all three agents have a median close to 100 steps" (:246).

**Comparison phrasing.**
- Magnitude with point values: "the winning probability of the agent is already decreased from 100% to below 40% for all mutation intervals. Employing 8 honeypots further decreases the probability to below 20% and 10 honeypots to below 10%" (:264); "employment of 2 honeypots is enough to decrease the winning probability from 77% down to 34%" (:264); "the highest movement interval still being 33% lower than the reference of no MTD" (:268).
- Ordering between agents: "the standard agent is performing slightly better on average, with a winning probability of 44%, compared to 26% with the careful and 30% with the aggressive agent" (:244); "The standard agents has throughout the highest winning chance" (:242).
- Threshold/crossover statements: "careful agent's winning probability dropping below the standard agent at around 4 honeypots and very close to it with 10 and above" (:234); "The aggressive agent is performing better for movement intervals below 60, and close for higher intervals" (:234) — note 60 is not a tested level.
- Recommendation-shaped: "This also implies that less perturbations are needed the more honeypots are in place." (:264). No explicit "A is the best choice when …" sentence in §6; the recommendation frame is left to the abstract (:29) and conclusion (:344).

## D. Narrative — the claims, in order

1. Framing caveat before any number: "the results reflect an assessment of honeypots and MTD considering an example configuration, and thus can be adopted to any network specifics using the proposed methodology" (:204).
2. "an increasing amount of honeypots in the network will decrease the chances of all three agents to win. But also the careful agent is highly affected as it does a horizontal scan and might identify a honeypot as a potential targets." (:234) — mechanism attributed to the agent's scanning pattern.
3. Standard agent's win probability falls earlier with honeypots; careful drops below standard at ~4 honeypots (:234; Fig 2a).
4. Under MTD interval 25 "the careful agent's winning probability is 0, as the IP mutation is happening before the agent chooses to attack" (:234; Fig 2b) — mechanism: full-scan phase exceeds the mutation interval.
5. Aggressive better than others for intervals below 60 (:234).
6. "The standard agents has throughout the highest winning chance, which is due to relatively quick actions on a randomly picked target." (:242).
7. Joint HP+MT: all agents decline with lower intervals and more honeypots; standard 44% vs careful 26% vs aggressive 30% on average (:244; Fig 1).
8. Steps (Fig 3): with HP+MT, aggressive max < 1000, careful median at 3000 ("doesn't succeed most of the time"), standard median and max < 100; no defence: all medians ≈ 100; HP only: steps drop "as an interaction with the honeypot end the round"; MT only: aggressive and careful medians rise to max, standard low median but third quartile at 3000 (:246).
9. §6.2: 2 honeypots take standard agent from 100% to < 40% across all intervals; 8 → < 20%; 10 → < 10% (:264; Fig 4).
10. Interaction claim: "with an increasing number of honeypots the mutation interval is having less influence on the winning chance. This also implies that less perturbations are needed the more honeypots are in place." (:264).
11. Network-size: in 10 hosts, 2 honeypots reduce 77% → 34% (:264; Fig 5a).
12. Objective: one sensitive host 82% vs all three 41%; with two honeypots 55% vs 5% (:264; Fig 5b).
13. §6.3: interval 25, 10 hosts → attacker wins 78%; 50 hosts → 48%; interval 50 → 33% and 23% (:268; Fig 6a). [As written the sentence reads as if a shorter interval gives the attacker the *highest* win chance and lengthening it *lowers* it — the inverse of the honeypot pattern and of the following sentence; recorded verbatim, not resolved here.]
14. "For 10 hosts, the mutation interval of 75 is already very close to the reference of having no MTD in place. For larger networks of 50 hosts, the increase of movement intervals does slightly increase the chance of winning, with the highest movement interval still being 33% lower than the reference of no MTD." (:268).
15. One-goal: MTD never pushes win chance below 40% for any interval; all-three-goals < 1% at interval 25 and 10% at interval 100 (:270–283; Fig 6b).

**Claims about the attacker from the data.** Yes, and this is the paper's §6.1 as a whole ("Agent Performance", :206). The agents are ranked by win probability and steps (:242, :244, :246) and each ranking is explained by a property of the agent's strategy: horizontal scan makes careful honeypot-prone (:234); full scan takes longer than the mutation interval (:234); "relatively quick actions on a randomly picked target" makes standard best (:242). The attacker-type ranking is a result in its own right, not only a robustness check on the defence.

## E. Sensitivity / parameter analysis

Present, but not labelled as such: the whole study IS a full factorial grid over Table 1 (:179–188), and the results sections read out one-at-a-time slices of that grid. Parameters and ranges: honeypots {0, 2, 4, 6, 9, 10}; movement time {None, 25, 50, 75, 100}; hosts {10, 50}; objective {one, all}; seed ×3; agent ×3. Design: grid/factorial ("Each combination of parameters was run 100 times", :200). Justification for the ranges: not stated. Reporting: figures only (Figures 1–6); no sensitivity table. Location: inside results (§6.2 and §6.3 are the honeypot-axis and MTD-axis sweeps; §6.1 is the agent axis). Claims supported: the honeypot × interval interaction (:264), network-size effect (:264, :268), and objective effect (:264, :270). Fixed parameters are declared but not varied (Table 2, :210–232); no sensitivity on step_limit, exploit probability (1.0), or costs, though the conclusion flags step_limit as a threat (:344).

## F. Discussion / limitations

No Discussion section. Interpretation is folded into §6 sentence-by-sentence (mechanism explanations at :234, :242, :246, :264). Related Work (§7) follows results and closes with a positioning sentence: "A simulation methodology combining honeypots and moving target defense, as described in this paper, has not been presented before to the author best knowledge." (:324) and the methodological justification for scripted agents over RL (:310, :324).

Limitations live in the Conclusion, verbatim:
- "Although the simulation is based on abstraction and many assumptions have to be taken, the result is of value if these assumptions can be sufficiently justified for the real world scenarios of practitioners." (:344)
- "The results of the case studies provided in Section 6 of this paper are only valid for the specific simulation parameters and can not be seen as general metrics, since the parameters in the simulation, such as limiting an attack to 3000 steps, may not accurately describe any real world scenario. They should be rather interpreted in relation within the simulation setting to measure the impact of the attacker types, network size, mutation intervals and honeypots." (:344)
- Results-section framing caveat: "It is important to state the results reflect an assessment of honeypots and MTD considering an example configuration" (:204).

Attacker-realism concessions: only the design-time statements that the standard agent "aimed toward a more realistic approach" (:119) and the aggressive agent "could be the behavior of a computer worm" (:129). No comparability caveat against other papers' numbers; no threats-to-validity list; no replication statement (code/data availability not stated).

## G. Transferable vs purpose-specific

**Transfers to an honours dissertation evaluating existing MTD mechanisms against a new attacker model on a simulator:**
- Two-table parameter declaration: a Varied table (:189) and a Fixed table (:232), same three columns, so the reader sees the grid and the frozen constants separately.
- The three-way termination rule stated as a list before any result (:192–198), and the horizon (step_limit) as a named fixed parameter (:228).
- "Each combination of parameters was run N times to compensate for randomness" as a one-sentence replication statement (:200).
- Results ordered attacker-first, then one defence axis per subsection (:204), with the order announced in the results preamble.
- The no-defence condition treated as one level of each factor (None / 0) rather than a separate experiment, so it appears on every figure's x-axis or legend.
- Explaining every attacker-vs-attacker difference by a named property of the attacker's rule set (:234, :242).
- A "results are only valid for the specific simulation parameters ... interpreted in relation within the simulation setting" caveat (:344) — but placed in Conclusion; a dissertation would move it to a Limitations section.
- Steps-to-goal box plots split by defence combination (Fig 3) alongside win-probability line charts.

**Artefacts of this paper's own purpose/venue:**
- Honeypot-count as the primary defence axis and the "win = exploit all sensitive hosts / lose = touch a honeypot" game, which is NASim's goal structure (:149, :155) — not an MTD-only evaluation.
- Recommendation-oriented framing ("optimal number of honeypots", :29) driven by a practitioner-deployment purpose.
- No Discussion/Limitations section and Related Work after Results — a 9-page workshop layout.
- No statistics beyond point estimates; no seeds-vs-scenario separation in reporting; exploit success probability fixed at 1.0 (:223).
- Figures carry the raw legend labels ("HP/MT", "OneGoal/HP") from the plotting script (:248, :300, :313, :318, :337, :340).
