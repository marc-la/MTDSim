# he2025 — evaluation-section anatomy

Source read: docs/sources/lit_review/3_2_he2025MTD-AD.md (full text; locators "L<n>" = md line) and docs/sources/lit_review/original/3.2_he2025MTD-AD.pdf (13 pp., text extracted per page with pypdf; locators "p<n>" = PDF page). The PDF's tables I–V and figures 1–7 are embedded as images, so table cell contents are NOT extractable from either source; where a table's structure is given below it is reconstructed from the prose that describes it, and said so.

Paper's own research question / purpose (one sentence, so its conventions are read against its purpose, not ours): propose MTD-AD, a framework that stochastically mutates the decision boundary of an anomaly-based NIDS (Kitsune), and show it defends against *practical packet-level* adversarial DoS attacks and against *adaptive* adversaries aware of the defence, on an IoT intrusion-detection dataset (Abstract L5; contributions L35–43; p1).

## B. Setup — what is declared before any result

- Network configuration(s): not a simulated network; a captured-traffic dataset, UQ-IoT-IDS-2021 (L213; p6), "a recent IoT intrusion detection dataset that spans a significant duration of time and includes a diverse range of commonly used IoT devices" (L213). One testbed: "Cameras, Google Nest, Lenovo Bulb, Raspberry Pi, Smart Clocks, Smartphones, and Smart TVs" (L215; p6), Fig. 3 (p7). Attacker on Kali Linux flooding "each IoT device over the wireless network" (Fig. 3 caption, p7); Raspberry Pi captures traffic (p7). Benign traffic = seven days per device (L223). Attack traffic = ACK/SYN/UDP flooding via LOIC on each device (L223). Packet counts per device: deferred to "Supplementary Material III" (L223). Number of configurations: one dataset; the per-device axis (7 device classes) is the effective "configuration" axis in every result table. How chosen: "recent", "diverse", and DoS chosen "as they exhibit distinct patterns … easily detectable by Kitsune. However, the LM attack has the ability to modify DoS attacks to evade detection by Kitsune entirely" (L223).
- Attacker model / scenarios: a formal threat model in §III.A structured as *Goal / Knowledge / Capability* paragraphs, each label italicised once (L99, L101, L87; p3). Three knowledge levels, italic-labelled once and abbreviated: "_Grey-box (GB)_", "_White-box (WB)_", "_Adaptive-knowledge (AK)_" (L103, L83, L85), summarised in TABLE I "SUMMARY OF THE THREE THREAT MODELS" (p3; image). Attacker capability: sniff and replay; "the attacker only has access to the last 10% of the training data" (L87). A realism ranking is stated up front: "the WB threat model poses the greatest challenge to defend against but is largely impractical in real-world scenarios. The GB threat model, being more realistic, is comparatively easier to defend against. Meanwhile, the AK threat model is perhaps the most realistic scenario and presents a more challenging problem" (L89; p3). Attack instances: LM at four maximum time delays (0.1, 0.3, 0.5, 0.7 s) with injected packets fixed at "the default value of 10" (L125–127), under GB and WB → named GBLM-0.1 … WBLM-0.7 (L267); GBFP with FGSM/JSMA/DeepFool/PGD → GBFP-F/J/D/P (L135, L267), bounds 0.5 s and ten packets "as the inter-arrival time of benign traffic typically ranges from 0.05 to 0.5 seconds in our dataset" (L137), truncated to first 10,000 malicious packets "following a similar approach taken by Han et al." (L139). TABLE II "OVERVIEW OF ATTACK CONFIGURATIONS" (p4; image). Adaptive attacks: GBLM-0.1 regenerated with surrogate threshold at 90/70/50/30/10 % of original (L329; p10).
- Defence conditions: one framework (MTD-AD) with three mutation techniques treated as the compared conditions: Feature Mapper Mutation (FM), Model Parameters Mutation (MP), Detection Model Mutation (DM) (L181–193; p5). Selection of these three from a wider candidate set was done "on a smaller dataset (details of the experiment can be found in Supplementary Material I)" (L179). Parameters: γ = 20, "We empirically set γ to 20 to introduce sufficient variation in the decision boundary while preserving performance", applied three times (L191); switch every n = 1000 packets, "for our network configuration, we set n = 1000" with the consequence "switching to a different model approximately every 0.2 seconds" at 5,000 pps (L207; p6); pool filter = discard any mutated model with FPR above baseline Kitsune (L199). "No defence" baseline: yes — called "the vanilla Kitsune model" (L249), "the undefended Kitsune" (L311), "baseline Kitsune" (L299, L303). The defender also has a formal model in §IV.A with the same Goal / Knowledge / Capability structure (L147–159), including a time goal: "the defender aims to detect flooding attacks within 20 seconds" (L147).
- Parameter table: no single parameter/value table. TABLE I summarises threat models and TABLE II attack configurations (both images; columns not extractable). No distributions are declared for any parameter; parameters are point values with a one-clause justification each (γ "empirically", n by packet rate, bounds by benign inter-arrival range).
- Replications: no runs/seeds/episodes stated for the attack or defence evaluations. The only replication count stated is for the efficiency experiment: "We generated 140 models for each MTD-AD technique and measured the probability of generating a satisfactory model" (L355; p11). Pool size actually used in VI.B–VI.D: not stated. Horizon: the dataset's captured traffic; the defender goal of 20 s (L147) is the only time horizon stated. Termination rule: not stated.
- Statistics: means only. "Table III provides an overview of the average ADR and RI" (L267); Table IV "the average change in ADR and MDR compared to the baseline model" (L317); Table V "average cost for generating one satisfactory model" (L355). No std, CI, min–max or significance tests stated anywhere. Two fitted relationships are reported instead: a linear slope per device in Fig. 6 ("The value in brackets indicates the slope of the line", L337) and a power law in Fig. 7 ("ADR = RI^k, where k is constant", L345). Success is decided by thresholds rather than by tests: attack success = ADR < 0.001 and RI > 0.12 (L261); defence success = ADR > 0.1 with MDR decrease ≤ 0.1 (L299).
- Anything else declared: Adversarial Robustness Toolbox for feature-level attacks, with C&W excluded "due to lack of support for binary output in the … ART implementation" (footnote, L149; p4). Hardware: not stated. Software versions: not stated. Cost is measured in relative units, not wall-clock: "The absolute time … depends highly on the computational resources and is hard to quantify. Therefore, we approximated the cost … with a base cost of 1 for executing the model and a cost of 2 for training the model" (L353; p11). Metric formulations deferred to Supplementary Material II (L227).

## C. Results — how the numbers are shown

- Order of results: an explicit roadmap paragraph opens §VI (L249–257): (1) attacks against vanilla Kitsune "to identify successful attack configurations"; (2) MTD-AD against the selected attacks; (3) diversity "to understand the variations"; (4) adaptive adversaries; (5) computational cost. The order is a funnel: §VI.A filters the attack set down to the one successful configuration (GBLM-0.1), which is then the sole attack used in §VI.B–VI.D; §VI.C is an explanation of §VI.B; §VI.D stresses the winner of §VI.B (FM only); §VI.E is cost. The reason is stated: attacks that fail the success criterion "will not be considered in MTD evaluations" (L279, L289).
- Figures in the evaluation portion (all images; chart type inferred from caption text only):
  - Fig. 3 (p7): testbed diagram; not a data chart.
  - Fig. 4 (p8): "The performance of the three attack types, measured by the ADR and RI. The red rectangular region indicates successful attack configurations." (L265) — a two-metric plot with ADR and RI as the axes, series = GBLM / WBLM / GBFP, success criterion drawn as a rectangle. Facets: not determinable.
  - Fig. 5 (p10): "Relative change in ADR and MDR between baseline Kitsune and Kitsune with DM, MP, and FM. A value of 0 on the y-axis means there is no difference, and values greater than 0 indicate that Kitsune with MTD-AD performs better. The dotted red line indicates the minimum acceptable values for each metric." (L303) — y = relative change vs baseline, series = DM / MP / FM, two panels or two metrics (ADR, MDR), threshold line drawn. Chart type: not determinable from text.
  - Fig. 6 (p11): "Relationship between RI and threshold % of adaptive attacks. The value in brackets indicates the slope of the line." (L337) — x = threshold %, y = RI, one line per device, slope annotated in legend.
  - Fig. 7 (p11): "The performance of adaptive Liuer Mihou against Feature Mapper Mutation: the shaded region indicates successful attack configurations." (L341) — ADR vs RI for adaptive attacks against FM; log scale ("ADR is linearly proportional to RI under a logarithmic scale", L345); success region shaded.
- Tables (all images; structure reconstructed from prose):
  - TABLE III "THE RI AND ADR OF ADVERSARIAL ATTACKS" (p8): rows = devices; columns = attacks "categorized into two groups: GBLM and WBLM attacks, based on their maximum time delay values (0.1, 0.3, 0.5, and 0.7), and GBFP attacks … FGSM (F), JSMA (J), DeepFool (D), and PGD (P)" (L267), each with ADR and RI. Compares attack configurations against undefended Kitsune per device.
  - TABLE IV "CHANGE IN DETECTION RATE AND DIVERSITY OF MTD-AD TECHNIQUES" (p10): rows = FM / MP / DM; columns = average ΔADR, average ΔMDR vs baseline, ASD, APC (L317). Compares defence techniques on effect and diversity in one table.
  - TABLE V "EFFICIENCY (EFFI.) OF MTD-AD TECHNIQUES, CALCULATED BY THE AVERAGE COST OF GENERATING A SATISFACTORY (SAT.) MODEL" (p11): rows = FM / MP / DM; columns = probability of a satisfactory model, unit cost, efficiency (L353–355).
- How the baseline appears: in Table III/Fig. 4 the baseline *is* the target (attacks measured on vanilla Kitsune); in Fig. 5 and Table IV the baseline is the zero line / the reference of a relative change ("relative change … compared to the baseline Kitsune", L299); in Fig. 6 adaptive-attack RI is measured "against undefended Kitsune" (L331–343). The baseline never appears as its own row or series; it is always the denominator or the origin.
- How comparisons are stated in prose:
  - Threshold/criterion statements dominate: "we define a successful attack as one that achieves an ADR below 0.001 while maintaining an RI above 0.12" (L261); "We allow a decrease of 0.1 in MDR compared to the baseline Kitsune … a successful defense requires an ADR above 0.1" (L299). Each threshold gets a one-paragraph justification (L261–263, L299).
  - Ordering: "only GBLM-0.1 manages to successfully evade detection for all devices while maintaining sufficient attack intensity" (L275); "only FM achieves a relative ADR greater than 0.1 for all adversarial flooding attacks. Furthermore, FM is the only MTD-AD technique with a decrease in MDR of less than 0.1 for all models" (L311); "MP … is the most efficient method overall … DM is the least efficient method" (L357–359).
  - Magnitude: "a variation of approximately 0.02-0.03 across all the devices" (L277); "most adversarial attacks targeting the Lenovo Bulb exhibit RIs exceeding 0.6, whereas attacks on SmartPhones only achieve an RI of approximately 0.12" (L269); "a 10% reduction in the threshold leads to a decrease of approximately 0.06 of the original RI" (L343).
  - Functional form: "the RI of the adaptive attack decreases linearly with the percentage of the threshold" (L343); "ADR grows polynomially with RI … ADR = RI^k" (L345).
  - Recommendation (rare, and directed at NIDS design rather than at choosing a defence): "it is imperative to develop a more fine-grained approach for NIDS that considers the specific characteristics of individual devices" (L277); "To improve the efficiency of DM, valid combinations of hyperparameters and detection models should be carefully selected for NIDS" (L359).

## D. Narrative — the claims, in order

1. RI disparity across devices is large regardless of attack; attributed to Kitsune operating network-wide and being "biased toward the traffic patterns associated with these high-activity devices", so the threshold is "relatively high for low-activity devices" (L269–271; p8–9).
2. GBLM: only GBLM-0.1 succeeds on all devices; larger max delay lowers RI; delay configurations differ by only ~0.02–0.03 in RI, so low-activity devices "are susceptible to all configurations of GBLM attacks" (L275–277).
3. WBLM: all fail the ADR criterion, so are dropped (L279). "Surprisingly, WBLM attacks demonstrate better RI compared to GBLM attacks despite their poorer ADR … counterintuitive because we expect the WB setting to be more effective" (L281); hypothesis: Kitsune's feature mapper causes a "discontinuous decision surface" — "Kitsune unintentionally applies gradient masking" — which the grey-box surrogate smooths over (L283–285).
4. GBFP: "in general, it proves to be ineffective"; gradient-based variants have lower ADR and RI than JSMA; dropped (L289). Explanation: JSMA "perturbs a single feature … disregarding inherent feature correlations"; GBFP's "main weakness" is that features are "generated independently in advance" ignoring sequential dependence (L291–293).
5. MTD-AD: "all three MTD-AD techniques have increased the ADR against GBLM-0.1 compared to the undefended Kitsune"; only FM passes both criteria for all devices (L311). Hypothesis registered: performance "is closely related to the diversity of models" (L313).
6. Diversity: "Surprisingly, models created via FM have the lowest ASD and the highest AC … yet they exhibit the best performance"; conclusion "unlike in ensemble learning, pursuing high diversity among models for MTD-AD is unnecessary and leads to worse performance", with a mechanism (single-model decision vs voting) (L319); plus a second mechanism for FM's MDR gain (feature mapper "optimized only for the first 20% of packets", L321).
7. Adaptive attacks: RI falls linearly with threshold %; "The ADR of all adaptive attacks is 0" against undefended Kitsune (L343). Against FM: "MTD-AD is resilient against adaptive attacks because only a few attacks against high-activity devices … are successful"; ADR = RI^k, "if the attacker wants to increase the maliciousness … the ADR of the attack has to increase polynomially" (L345).
8. Efficiency: MP most efficient despite lowest success probability; FM highest probability but retraining is costly; DM least efficient (L357–359).

Claims about the ATTACKER's properties from the data: yes, and prominently. The whole of §VI.A is attacker characterisation on the undefended target: which attack knowledge level is actually more dangerous (grey-box beats white-box, L281–285), which attack generator is viable (LM vs FP, L289–293), and how attack parameter (delay) trades evasiveness against maliciousness (L275–277). §VI.D characterises the adaptive attacker's trade-off as a law (linear RI loss, polynomial ADR growth, L343–345). These are stated as observations plus explicitly labelled hypotheses ("We hypothesize that …", L283, L313, L317), and the attacker findings are used as the selection step for the defence evaluation (the attack set is pruned to GBLM-0.1 before any defence is tested).

## E. Sensitivity / parameter analysis

Present, but never labelled "sensitivity" and never given its own section; it is embedded in results as attack-side parameter sweeps:

- Max time delay of LM: four levels 0.1/0.3/0.5/0.7 s, one-at-a-time with injected packets held at 10 (L125–127); justified by "time delays crucial for achieving the attack's maliciousness" (L125). Reported in TABLE III and Fig. 4 (p8). Used to select the single attack configuration (GBLM-0.1) carried forward, and to claim the small RI spread across delays (L277).
- Surrogate threshold fraction for the adaptive attacker: 90/70/50/30/10 % (L329), one-at-a-time; no stated justification for the range. Reported in Fig. 6 (RI vs %) and Fig. 7 (ADR vs RI), p11. Used to support the resilience claim and the ADR = RI^k relationship (L345).
- Device class is a second, categorical axis in every result (7 devices), and drives claims about low- vs high-activity devices (L269, L277, L345).
- Defence-side parameters are NOT swept: γ is "empirically set" to 20 (L191), the switch period n = 1000 is fixed by argument (L207), and the pool-filter rule is fixed (L199). The choice among candidate mutation techniques was made by a preliminary experiment "on a smaller dataset" reported only in Supplementary Material I (L179).
- Grid/factorial: none; each sweep varies one factor while everything else is fixed.

## F. Discussion / limitations

Discussion is split: interpretation and mechanism hypotheses are folded into §VI (each subsection ends with a "We hypothesize" / "This can be attributed to" paragraph: L269, L283–285, L291–293, L319–321, L357–359); limitations are a separate §VII "LIMITATIONS AND FUTURE WORK" (p11–12, L361–369) organised as three italic-labelled paragraphs, each pairing one limitation with one future-work item. No "threats to validity" heading. No comparability caveat against other MTD or adversarial-defence papers (no numerical comparison to prior defences is made anywhere; the only comparison is to the undefended baseline). Attacker-realism concessions appear in the threat model (§III.A) rather than in §VII.

Verbatim limitation sentences:
- "_Realistic Maliciousness Evaluation:_ Our experiments analyzed the maliciousness and evasiveness from a theoretical perspective, where the relative intensity is calculated analytically based on the interarrival times of packets. … it's important to note that the intensity of the attack in practice may differ due to irreducible processing and propagation delays during transmission." (L363–365; p11–12)
- "_MTD-AD Overhead:_ We have mostly analyzed the cost of obtaining the models but not switching between models because it falls outside the scope of our work. However, we anticipate that the overhead of switching between trained models would be negligible for relatively small networks … Nevertheless, for high-speed networks, switching between models could potentially result in higher overheads or packet loss." (L367; p12)
- "_Additional Mutation Operations:_ The MTD-AD framework we propose is highly versatile and open to extensions. … it is possible to relax the threat model to include a more sophisticated design of MTD-AD. For example, if the threat model allows for malicious traffic, the evaluation stage could incorporate MDR as a criterion" (L369; p12)
- Attacker-realism concession (in threat model, not §VII): "the WB threat model … is largely impractical in real-world scenarios … the AK threat model is perhaps the most realistic scenario" (L89; p3).
- Scope concession inside results: "The exact criteria for the success of an adversarial attack rely on the specific context and the level of disruption intended by the attacker. In our work, we define a successful attack as …" (L261; p8); "While the acceptable level of packet loss depends heavily on the specific context, prior research suggests packet losses ranging from 5% to 10% have a significant impact on user experience [48]. Our observations during the experiments also confirm this." (L263)
- Statement of what the defence claim rests on: "It requires minimal knowledge on the defender's part and demonstrates robustness against both original and adaptive adversarial attacks." (L377; p12)

## G. Transferable vs purpose-specific

Transfers to an honours dissertation evaluating existing MTD mechanisms against a new attacker model on a simulator:
- The *Goal / Knowledge / Capability* threat-model template, with each attacker variant italic-labelled and abbreviated once and then used as a name throughout (GB/WB/AK; GBLM-0.1), and a one-paragraph realism ranking of the variants stated before any result (L89).
- A defender model written in the same three-part template as the attacker model (§IV.A), so the two sides are declared symmetrically.
- Declaring explicit success criteria with a justification paragraph each (ADR < 0.001 ∧ RI > 0.12; ΔMDR ≤ 0.1 ∧ ADR > 0.1) and then drawing them on the figures (red rectangle, dotted line, shaded region).
- A roadmap paragraph opening the results section that names each subsection's question and the order's logic (L249–257).
- Funnel order: characterise the attacker on the undefended target first, prune to the configurations that matter, then test defences only against those (with the pruning rule stated).
- Pairing every result subsection with a mechanism hypothesis, explicitly flagged "We hypothesize", and separating "surprising" from expected findings.
- Reporting the baseline as the origin of a relative-change plot rather than as its own series.
- Limitations as short labelled paragraphs, each limitation paired with the future work that would lift it.
- Naming the per-configuration justification of every fixed parameter in one clause (γ "empirically", n from packet rate, bounds from benign inter-arrival range) even when no sweep is done.
- Measuring cost in relative units with a stated rationale when wall-clock is machine-dependent (L353).

Artefacts of this paper's own purpose/venue:
- No replication/seed/CI reporting at all: the evaluation is on a fixed captured dataset, so "runs" are not the unit; the only count (140 models) is for a probability estimate. A simulator study cannot inherit this.
- The device-class axis as the main "configuration" facet (7 IoT devices) — a dataset artefact.
- Attack-side parameter sweeps only; defence parameters fixed by argument — because the paper's contribution is the defence and the attack is the instrument.
- ML-specific metric set (ADR, MDR, RI, ASD, APC) and the diversity-vs-ensemble argument.
- Supplementary material carrying technique selection, metric formulations and dataset counts (IEEE TDSC convention).
- "Adaptive adversary" as a separate results subsection (a NIDS/adversarial-ML convention, here claimed as a first).
- Limitations restricted to three items with no threats-to-validity or comparability discussion; no comparison to other defences.
