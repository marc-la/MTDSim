### Relevance class

**C — Contrast / adjacent.** Kim et al. is one of the five §IV-B cross-section points in [`../sources/LIT_REVIEW.md`](../lit_review/LIT_REVIEW.md) (§IV-B item 5, line 193); it is cited specifically to anchor the *scripted-fidelity* row of Table II for a CKC-aware MTD defender. The contrast is in *scoping resolution* — Kim et al. organise both defence and attacker behaviour at the Cyber-Kill-Chain phase level, whereas this dissertation's L1–L2 pipeline ([`../specs/architecture.md`](../../implementation/architecture.md) §(d)–(e)) operates at ATT&CK technique granularity. The paper does not inform an L0→L4 design decision; it bounds the comparison Table II makes against the cross-section.

### CKC-phase scoping of the MTDID defender and attacker

**Source locator:** §1 Introduction (framework framing); §4.3 (CKC seven-step enumeration); §4.4 + Table 3 (CKC × MTD sub-technique matrix); §5.2 + §6.1.1 (attack model and Poisson workload).

**Paraphrase:** MTDID organises proactive defence by mapping shuffle / diversity / redundancy sub-techniques onto digital artefacts (extended from MITRE D3FEND across the virtualisation architecture and TCP/IP stack) and then onto the seven CKC phases (reconnaissance, weaponisation, delivery, exploitation, installation, C2, actions on objectives). ATT&CK techniques are pulled in *taxonomically*: Table 2 lists representative ATT&CK technique IDs (e.g., T1016, T1190, T1059, T1071, T1547) bucketed under each CKC phase to populate the matrix cells, and Table 3 then marks (△) which MTD sub-technique covers which (phase, ATT&CK-ID) pair. ATT&CK provides the technique vocabulary; CKC supplies the structural ordering. The evaluation collapses this further. §5 explicitly notes that "the overlap in time between each phase is out of scope" (§5.2), Weaponisation is excluded ("the stage of weaponization can be ignored because the exploit is open in the public database", §5.2), and the seven CKC phases are folded into three measurement categories — REC, DEI (delivery+exploitation+installation), C2A (§6.1.2). The realised attack is a single automated script targeting one CVE (CVE-2021-41773 path-traversal/RCE on Apache httpd 2.4.49) with arrivals drawn from a Poisson process at rate 0.2/min (§6.1.1), the security metrics computed phase-by-phase (`ASP_REC`, `AST_DEI`, `ART_C2A`, etc.) over those collapsed categories.

**Quote (if essential):**
> "We assume that scenario-based attacks conduct the activities in phases of the CKC … This work proposes a single attack scenario and follows sequential steps. The overlap in time between each phase is out of scope." (§5.2)

**Maps to:** [`../specs/architecture.md`](../../implementation/architecture.md) §(d) (L1/GAP operates at ATT&CK technique resolution, with edges encoding inter-technique dependency rather than CKC-phase membership) · [`../specs/architecture.md`](../../implementation/architecture.md) §(e) (L2/GASP conditions on motivation-mediated subgraphs, not on phase-bucketed technique lists) · [`../sources/LIT_REVIEW.md`](../lit_review/LIT_REVIEW.md) §IV-B item 5 (line 193) and Table II row for Kim et al. (line 207) — scripted fidelity, no persistence / adaptivity / stealth / incentive-awareness.

**Disposition for this thesis:** **contrasted-against.** The contrast is one of *scoping resolution*, not correctness: CKC phases are a coarser quantisation of the same attacker behaviour ATT&CK techniques describe at finer grain. MTDID demonstrates that the phase-level grouping is *adequate for mapping defender coverage* (which mechanism mitigates which broad phase) and is honest about what its evaluation gives up — sequential, non-overlapping phases driven by a single CVE script — but does not reach behavioural fidelity at either resolution. This dissertation operates one rung finer: ATT&CK techniques as the unit of attacker behaviour and the dependency graph between them as the structural carrier, so that an attacker reasons over individual techniques (and their inter-technique preconditions) rather than over phase buckets. The §IV-B Table II placement (scripted) follows from the executed attack model (single CVE, automated script, collapsed phases) rather than from the framework's matrix breadth.

## Attacker model, extracted for the predicate tests (2026-10-12)

Source: the published PDF (FGCS 181, 108419). Pages are as printed; § numbers are the paper's. This section takes **only the executed attacker model** (§5.2, §6.1, Eq. 2, Table 5). §1 and §4.3 describe attackers in general for the framework; they are listed apart under G, because nothing in them enters the attack (B5, B7).

### A. What the attacker is
- A1 "We generate automated exploits to run Remote Code Execution (RCE), which is one of the MITRE ATT&CK offensive techniques (i.e., T1059)." (§5.2, p. 7)
- A2 "The automated attack consists of four stages of the CKC and its objective is to compromise a vulnerability (i.e., CVE 2021–41773) of an Apache web server." (§5.2, p. 7)
- A3 "The attacker aims to obtain a bash shell prompt without authentication if its exploitation succeeds." (§5.2, p. 7)
- A4 The attacker targets "a specific version of a web service", and its code runs "one of the proof of concept (POC) codes in a public database". (§5.2, p. 7)
- A5 "it is only targeting an Apache web server because of its weapon" (§6.1.1, p. 9)
- A6 "The objective of the attacker is to obtain a shell connection between an attacker and a victim in order to access a shell terminal without authentication." (§6.1.1, p. 9)
- A7 "Their primary goal is to gain unauthorised access to the target system." (§6.1.3, p. 9)
- A8 The attacker runs on a Raspberry Pi 4. (§6.1, p. 9)

### B. Stages, in order
- B1 Weaponization "can be ignored because the exploit is open in the public database". (§5.2, p. 7)
- B2 REC: "It assumes that an attacker has a lack of network information about a target so it first scans the IP addresses of web servers that open the HTTP port 80. Due to time constraints, an attacker can scan only a fraction of the IP address space depending on the repeat parameter and attempt to collect the service information of a discovered target if it finds any serving web servers within the range of scanning IP addresses (e.g., MTD interval)." (§5.2, p. 7)
- B3 DEI: the attacker delivers "an exploit code of T1059 through the network and waits for the connection request for obtaining a shell prompt … A shell prompt provides a set of commands that an attacker can move to the next stage based on the objectives of the attacks." (§5.2, p. 7)
- B4 C2A: "an attacker keeps retaining the hidden connection between an attacker and a victim. The attacker can install tools or crafted code in a hidden directory in order to avoid detection by the target's defense solutions." (§5.2, p. 7)
- B5 "This work proposes a single attack scenario and follows sequential steps. The overlap in time between each phase is out of scope." (§5.2, p. 7)
- B6 "The attacker first attempts to find an IP address of a target in a network and then collects information on the target's web services. If the attacker found the web service and its vulnerable version, it tries to compromise a target by using its prepared weapon." (§6.1.1, p. 9)
- B7 "We assume that the attackers follow the predefined sequence of phases based on CKC." (§6.1.3, p. 9)

### C. Evasion
- C1 "After the attacker succeeds to connect to a victim, it assumes that creating an outbound connection is attempted in order to evade the detection by a defense system such as a network intrusion detection system (NIDS) or a firewall." (§5.2, p. 7)
- C2 B4's hidden directory, and "The defense solution has limitations in securely monitoring all outbound connections, an attacker may attempt to create a way to create an outbound hidden connection." (§5.2, p. 7)
- C3 **No IDS in the testbed.** The system model lists SDN switches, web servers, a legitimate client, the attacker, the ONOS controller and a DNS server (§5.1, p. 7; Fig. 4). The No-MTD baseline handles packets "without any defense mechanisms" (§6.3, p. 10). The paper never says outright that there is no IDS; it lists none.

### D. Workload and budget
- D1 Attacks arrive as a Poisson process, ATK_λ = 0.2/min. (§6.1.1, p. 9; Table 4)
- D2 The attacker scans 4096 addresses "on each trial", with "a limit to the number of scanning attempts up to the number of repetitions". Repeat = 5, so M = 4096 × Repeat of N = 65,535 addresses. (§6.1.2, p. 9; Table 4)
- D3 T_ATK "denotes the time when an attacker begins probing the target system". (§6.1.3, p. 10)

### E. Time and the MTD
- E1 The naive configuration "triggers the operations of all MTD techniques at the same time on a regular basis" (§5.3.1, p. 8), every T_MTD = 300 s (Table 4).
- E2 Eq. 2: ASP = ∏_k (AST_k / T_k) · ASP_k. "At each CKC phase (k), attackers can determine the remaining available time (T_k) after successfully completing the preceding step", where T_k = T_MTD − T_ATK − Σ_{i<k} AST_i. (§6.1.3, p. 10)
- E3 Redundancy resets resources every T_RST = 600 s, and "this study assumes that the connection between an attacker and a target is disconnected during either T_DEI or T_C2A". (§5.3.1, p. 8)
- E4 "the network shuffling technique is ineffective when attackers are already successful in installing malicious code for the connection between a victim and a C&C server via reverse connections". (§4.4, p. 7)
- E5 Table 5 (p. 11):
  - AST_vIP is 403–572 s under the shuffling systems, longer than T_MTD.
  - ART_C2A is ≫ 600 s without redundancy, and 268 s and 199 s with it.
  - ASP_DEI = ASP_VUL in every row.

### F. The authors' own bounds
- F1 "by exploiting the vulnerability (Apache CVE-2021-41773), the scope of our assessment is restricted. Therefore, our future work will take into account more advanced threat models" (§6.4, p. 11)
- F2 The testbed "may not be substantial in replicating real-world conditions and accurately capturing the diverse range of attack scenarios". (§6.4, p. 11)

### G. Framework text that is not the model
- G1 "attackers are patient enough to continue to attack a target until they achieve their goals" (§1, p. 1)
- G2 Reconnaissance "can include either passive, active, or both". (§4.3, p. 4)
- G3 Delivery: attackers "should be patient to circumvent any defense services … by masquerading as normal users, they should conceal their suspicious activities". (§4.3, p. 4)
- G4 C2: "According to the objectives of attackers, they may attempt either to access resources or sensitive user data … or to escalate the privilege". (§4.3, p. 4)

### Findings for the thesis

Findings 1 and 2 were applied on 2026-10-12, Marc ratifying both; no mark moved.
1. **Appendix B row 1 qualifier.** "over an extended period, across MTD deployments" would give Kim a yes (E5), and so a full mark. The discriminator in the evidence is a bounded attempt against a campaign that keeps going. Proposed wording: "over an extended period, until it reaches its objective, however many MTD deployments that takes".
   - Kim: no (D2 budget; E3; the next arrival starts uninformed, B2).
   - Baseline attacker: yes (it carries on through every disruption).
   - Masud et al.: no (each interval's paths are computed afresh).
   - APT attacker model: yes.
2. **§3.3.2 row 8 sentence.** "that is the authors' model of the attack, not a prediction the attacker makes" contradicts E2's wording ("attackers can determine"). Proposed: "its success probability at each stage depends on the time left before the next MTD deployment, which the paper says the attacker can determine (p. 10), but no technique uses it."
3. **Correction to the 2026-09-07 pass.** "holds the outbound connection until the next MTD trigger severs it" is wrong. Shuffling does not sever a reverse connection (E4); only redundancy's reset does (E3, E5).
4. **Every other claim in the §3.3.2 Kim paragraph checks out** against A–E: the four stages in a fixed order, the scan, the version, one Apache vulnerability, the reverse shell, a new run at a random time, no knowledge carried over, the p. 7 quote, the absence of an IDS (C3: listed nowhere), and a disrupted attack failing (E3).
