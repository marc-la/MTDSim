Locator convention: section / equation / figure as printed, plus `l.N` = line in the source markdown. "unverified" = not pinnable in the text read. Page numbers only where the paper's own ToC or a prior extraction pins them.

Column key. **persp** = attacker-side / defender-side / network-state. **role** = eval (evaluation metric reported), RL-feat (RL-agent input feature), reward (reward term), stop (stopping rule / termination checkpoint), param (model input parameter, listed so it is not mistaken for a result), cited (named only as prior work's metric, not computed in this paper).

Zhang notes.
- **One name, two quantities inside Zhang.** MTTC is defined in §3.4 per target host ("compromise a target host") but reported in §5 as the time to reach NCR 0.8 (80 % of nodes). The reported number is a *campaign-level time-to-threshold*, not a per-host mean.
- **One acronym, two quantities.** "SA" = system availability (Alavizadeh, l.210) and Security Assessment (Torquato, l.238).

- No detection, stealth, action-count, or per-attempt success metric appears anywhere in Zhang.

Ho notes.
- **ASR in Ho is per attempted action, not per host or per run**: numerator = compromised hosts, denominator = attempted SCAN_PORT/EXPLOIT_VULN/BRUTE_FORCE actions. It is a hosts-per-action yield, so it is ≤ 1 only because each compromise needs at least one action.
- **MTTC in Ho is a mean event duration**: the mean of the durations of SCAN_PORT/EXPLOIT_VULN/BRUTE_FORCE events, not time from start to compromise and not per-host. Its discussion (l.517) nonetheless reads it as "the average time it takes for attacker to compromise the network".
- **HCR = Zhang's NCR** (same ratio C_t/T_host), renamed; Ho uses it as a feature, never as a stopping rule. HCR is also called "Host Compromise Ratio" (Tables 4–5) and "Host Compromised Ratio" (§3.3.2).
- Ho's §2.3.1 attributes APV/ESP/AI to [19] = Sharma 2020, while §2.3 attributes T-HARM path metrics to "Hong et al. [19]" — Ho's own citation keys disagree ([19] is Sharma, [29] is Hong 2018).
- Detection: none measured. "more opportunities for detection" (l.545) and "the model can detect any ongoing attack" (l.521) are prose readings, not metrics.
- Ho's "Attack Stage" is the only quantity in the whole lineage that exposes the attacker's in-flight state to the defender; it is a feature, not an evaluation metric.

Tay notes.
- **Tay's MTTC ≠ Ho's MTTC in words**: Tay defines it as the average time "to successfully breach… after identifying a potential vulnerability" (a time-to-breach), Ho as the mean duration of SCAN_PORT/EXPLOIT_VULN/BRUTE_FORCE events. They share one model and one codebase (Ho l.35), so the code computes one quantity under both names; see code section.
- **Tay's HCR ≠ Ho's HCR in words**: Tay includes hosts "at high risk due to identified vulnerabilities"; Ho's Eq. 10 counts compromised hosts only.
- **Tay's APE ≠ Ho's APE in words**: Tay describes a CVSS-severity × topology × accessibility score; Ho's Eq. 5–6 is a mean new-vulnerability percentage along the shortest path.
- No per-metric formula or reward means Tay's five evaluation metrics are defined only by reference to the shared code / Ho.
- The only detection-related quantity in the whole lineage is Tay's **attacker detection rate**, and it is a defender-information parameter, not a measured attacker property.

## Synthesis

### (a) Every attacker-side metric (all papers; role in brackets)

- **Zhang 2023**: MTTC [eval, primary; time to NCR 0.8]; MTTF [interpretation]; T_Aphase2 [model]; number of interruptions / attempt limit [stop, per host]; time penalty [param]; cited: AC, RoA, ACD, average attacking time.
- **Ho 2024**: ASR [RL-feat, reward, eval]; A_t attempted attacks [component]; MTTC [RL-feat, reward]; Attack Stage [RL-feat]; RoA with AC = time to exploit [RL-feat, reward, eval]; cited: attack cost, return on attack, attack effort (Brown), attack probability, attack coverage, scanning hits, attacker/defender effort, ESP, attack stage-based success metrics, MTTC score (Zhang).
- **Tay 2024**: ASR [eval]; MTTC ("MTCC") [RL-feat, eval]; ROA [eval]; cited: attack efforts, cost of attacks, duration to breach each point in an attack path, Pr (probability of attack success on paths), Cost on attack paths (AC), Return on attack paths.
- **McQueen 2006**: time-to-compromise T_pi / T [eval]; P1, P2, u [model]; t1, t2, t3 [model]; ET expected number of tries [model]; m, AM/V skill parameters [param]; binary open/closed door [rejected]. Companion: P_e chain Pt·Pa·Pb·Ps·Pc; total TTC (fixed + variable); cited P_A, (1−P_E), P_ND, P_SE, "time" and "effort" metrics. Lineage: MTTC (Leversage), β-TTC (Zieger), Maleki's success-probability-vs-time/cost.

### (b) Anything on detection / stealth / tempo / rate

- **No paper in the lineage measures attacker stealth or detection as an outcome.**
- Tay §5.3/§6.4: "attacker detection rate" / sensitivity — the fraction of attacker-action information fed to the defender during training (0–100 %); an independent variable on the defender's input, not a property of the attacker (code: a Bernoulli mask on the `attack_type` feature only, mtd_ai_training.py:419–428).
- Tay §3.2 (citing Hong 2018): "longer attack durations increase the chances of detection" — a claimed consequence, not a metric.
- Ho: prose only ("more opportunities for detection", l.545; "the model can detect any ongoing attack", l.521). Ho's Attack Stage feature gives the defender the attacker's current stage with no detection model.
- McQueen companion (cited from Major): P_ND "probability that the attack goes undetected"; "probability of an attack escaping detection". McQueen rejects Major's "detected ⇒ defeated" assumption for cyber.
- Tempo / rate: Ho **ASR** is a per-action yield (hosts per attempted action); Ho **MEF** is the defender's rate (MTDs per unit time); Ho **TSLM** and Tay "time since last MTD" / "intervals between MTD deployments" are defender tempo. Zhang's **MTTC at NCR 0.8** is the only campaign-pace quantity (time to reach a breadth threshold). The code's RL-head HCR is in effect a 60-s compromise rate (not so named in any paper). Ho's cited "scanning hits" (ID-HAM) is the only reconnaissance-rate quantity, and it is cited.
- Zhang's MTTC/MTTF equivalence and McQueen's "TTC decreases over time unless constant defender effort" (§6 p.15) are the only time-dynamics claims.

### (c) Actions or attempts per compromise

- **Ho ASR** = C_t / A_t (Eq. 11) — its reciprocal is attempted actions (SCAN_PORT + EXPLOIT_VULN + BRUTE_FORCE) per compromised host. It is the only lineage *evaluation* metric that normalises by attempts.
- **McQueen ET** (Eq. 4; Fig. 5 "Average number of attempts to compromise a component") — expected tries per compromise in Process 2; 1 for an expert.
- **Zhang**: a per-action attempt limit and interruption threshold (§4.4.2), a stopping rule with no reported count.
- **Code**: `current_host_attempt` and `cumulative_attempts` are logged per attack row (attack_statistics.py:25–40) but never aggregated; the E-head ASR denominator counts all three action types, the RL heads count SCAN_PORT only.
- Tay: none.

### (d) How far the attacker gets (reach / breadth)

- **Zhang NCR** — compromised ÷ total hosts; used only as the 0.8 stopping checkpoint (§5 l.420), never reported as an outcome (every run reaches it by construction).
- **Ho HCR** — the same ratio (Eq. 10), an RL feature and reward term; not one of Ho's four evaluation metrics.
- **Tay HCR** — "compromised or at high risk"; RL feature only.
- **Ho APE / Tay APE** — exposure of the shortest path to the target (network-state, not attacker progress).
- **McQueen** — no breadth measure; per-component TTC on the dominant path, compromise type "root access from a launch site".
- Cited only: attack coverage (EVADE, Ho), Pb perimeter breach and Ps (McQueen companion).
- Code: `host_compromise_ratio` at checkpoints 0.1…0.9 (evaluation.py:146) and the scorer's compromise counts, split by vector (vuln / reuse-password / password-spray) and exposed vs non-exposed.

Where one name covers different quantities:
1. **MTTC covers at least five quantities.** McQueen: analytic expected time per component. Zhang: the campaign time to 80 % compromise, averaged over runs, despite a per-target-host definition in §3.4. Ho: the mean duration of a single attack event. Tay: the time to breach after a vulnerability is identified. Code: Ho's event mean, plus a second same-named function that divides total action time by compromised hosts. Zhang and Ho also give it opposite units of analysis: per campaign vs per action event. The Zhang→Ho handover happened with no note of the change (Ho §2.1.1 reports Zhang's "MTTC score" as if it were the same metric).
2. **HCR vs NCR.** One ratio under two names (Zhang NCR = Ho HCR). Tay's HCR widens the numerator to hosts "at high risk", and the code's RL heads narrow it to a 60-s window.
3. **ASR** is defined only by Ho, and only per attempted action. Tay reports an ASR with no definition. McQueen has no ASR at all; its success quantities are probabilities (P1, u, Ps), not observed rates. So the lineage has no per-run or per-host success rate.
4. **APE** covers two quantities: Ho's mean new-vulnerability percentage along the shortest path, and Tay's CVSS × topology × accessibility score. The code implements Ho's.
5. **RoA** covers three: Ho's per-host risk ÷ time-to-exploit, and the system sum over all attack paths (Eqs 8–9); the Alavizadeh-lineage RoA that Zhang/Tay cite undefined; and the code's per-vulnerability value for the last exploited vulnerability.
6. **SA** means two things inside Zhang (system availability; Security Assessment). **SAPV** means three things across Ho and the two code heads.
