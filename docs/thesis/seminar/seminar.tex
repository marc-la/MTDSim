\begin{frame}{MTD is proposed against APT attackers, but rarely tested against one}
\begin{columns}[T]
\begin{column}{0.50\textwidth}
\begin{itemize}
  \item \textbf{Advanced persistent threat (APT)}: one objective, one target, months or years \src{Alshamrani 2019}
  \item Volt Typhoon: at least five years inside US critical infrastructure; its reconnaissance stayed valid \src{CISA 2024}
  \item \textbf{Moving target defence (MTD)}: keep changing the network, so what the attacker learned goes out of date \src{Cho 2020}
  \item Yet MTD is tested against attackers far simpler than an APT \src{Jalowski 2026}
\end{itemize}
\end{column}
\begin{column}{0.47\textwidth}
  \centering
  \includegraphics[width=\linewidth]{fig_3-1-3a_attack_flow_volt_typhoon}\\[1mm]
  {\scriptsize Volt Typhoon's intrusion as an \textbf{attack flow}: the steps an analyst recorded from the threat report, in order}
\end{column}
\end{columns}
\takeaway{\textbf{Research question:} How does MTD perform against APT attackers?}
\end{frame}
\note[itemize]{
\item \textbf{0:15 to 1:30.} Open on Volt Typhoon: five years inside, never detected, signing in with stolen valid accounts.
\item Its reconnaissance stayed valid because nothing moved. MTD's idea: keep moving, so stolen knowledge goes stale even if the attacker is never detected.
\item Point at the attack flow: ``This is what a threat report gives us: the steps, in order. Hold on to this picture; it is the raw material of my attacker.''
\item The gap: MTD is proposed against APTs, but tested against simple scripted attackers. Read the research question aloud.
\item Transition: ``To test that, I need an MTD simulator and an attacker. Here is the simulator.''
}

\begin{frame}{Previous work: MTDSim and its scripted baseline attacker}
\begin{columns}[T]
\begin{column}{0.50\textwidth}
\begin{itemize}
  \item \textbf{MTDSim}: UWA's MTD simulator \src{Brown 2023; Zhang 2023; Tay 2024}
  \item 50 hosts in four levels, from exposed endpoints to target hosts
  \item Seven \textbf{MTD mechanisms}, one deployed every \textbf{deployment interval} (200\,s by default):
  \begin{itemize}
    \item \textbf{host layer}: IP shuffle, two topology shuffles
    \item \textbf{service layer}: port shuffle, OS and service diversity
    \item \textbf{credentials}: user shuffle
  \end{itemize}
  \item \textbf{Baseline attacker}: six \textbf{attack actions} in a fixed order
\end{itemize}
\end{column}
\begin{column}{0.47\textwidth}
  \centering
  \includegraphics[width=\linewidth]{fig_2-2-1a_network_model}
\end{column}
\end{columns}
\end{frame}
\note[itemize]{
\item \textbf{1:30 to 2:30.} This is the work I inherit. Brown built it, Zhang added time, Tay added MTDShield, a reinforcement-learning agent that picks which mechanism to deploy.
\item Point at panel (b): each part of a host has a mechanism that moves it. \textbf{Remember the two layers}: the host layer moves where hosts are; the service layer moves what runs on them. The results hinge on this split.
\item The baseline attacker runs the same six attack actions in the same order, every run.
\item Transition: ``Is a fixed procedure like that a fair stand-in for an APT? I checked.''
}

\begin{frame}{A Petri net picks the next tactic; MTDSim's attack actions carry it out}
\begin{columns}[T]
\begin{column}{0.50\textwidth}
  \centering
  \includegraphics[width=\linewidth]{fig_4-4c_runtime_loop}
\end{column}
\begin{column}{0.47\textwidth}
\begin{itemize}
  \item Next tactic drawn by how often the attack flows took that step
  \item \textbf{Tactic-to-action mapping}: 8 of 15 tactics run an attack action; 7 are \textbf{unmapped} (e.g.\ Exfiltration) and only take time
  \item \textbf{Tactic duration}: up to 45\,s on average
  \item \textbf{Failure matrix}: after a failure, reweights the next tactic (failed Initial Access $\to$ Reconnaissance: 0.06 becomes 0.75)
  \item Threat reports record no timing or failures: declared, then stress-tested
\end{itemize}
\end{column}
\end{columns}
\end{frame}
\note[itemize]{
\item \textbf{4:45 to 6:15.} Walk the loop once with your finger, steps 1 to 6: token's tactic out; mapped to an attack action; runs for the tactic duration; MTDSim returns success or failure; after failure, the failure matrix reweights; token moves on.
\item Petri net = generalised stochastic Petri net, the convention in MTD evaluation. Timed transition = the tactic duration; immediate transitions = the choice of next tactic.
\item The ceiling: MTDSim's attack actions only find and compromise hosts. Collection, Exfiltration and Impact have nothing to act on, so the model steals no data. Say this plainly; it is the honest bound.
\item Where CTI is silent I declared values, before any result, and varied them afterwards.
\item Likely questions: ``Why these durations?'' $\to$ backup \textit{Tactic durations}; ``Formal definition?'' $\to$ backup \textit{The Petri net}.

\begin{frame}{Limitations: what the result does not show}
\begin{itemize}
  \item \textbf{One simulator}: MTDSim's default 50-host network; deployments cost nothing
  \item \textbf{Six attack actions cap the model}: 7 of 15 tactics unmapped; no data theft, no impact, no IDS to evade
  \item \textbf{Declared values}: tactic durations and failure matrix by judgement; only the 45\,s duration moves NCR much, and the ranking holds from a quarter to four times it
  \item \textbf{Small corpus}: 38 attack flows, 18 attributed to a known group; three attack profiles rest on 5 to 7
  \item \textbf{Cause not isolated}: tactic durations or the order of tactics; MTDSim's disruption rules were written for the baseline attacker
\end{itemize}
\end{frame}
\note[itemize]{
\item \textbf{12:45 to 13:45.} State these yourself before anyone asks; examiners mark you for it.
\item The headline does not say ``MTD fails against APTs'' or ``my attacker is the realistic one''. It says the ranking \emph{can depend} on the attacker model.
\item The declared values: fixed before any result; halved and doubled one at a time; ranking re-run at both ends of the one value that matters.
\item The disruption rules are MTDSim's, kept as its papers describe them; both attackers meet the same rules, so the comparison is fair, but an APT might not be disrupted the way the rules assume.
\item Likely question: ``How do you know the code does what you say?'' $\to$ backup \textit{Verification}.

\begin{frame}{Backup: why the APT attacker model compromises less with no MTD}
\begin{itemize}
  \item Unmapped tactics take 34 to 57\,\% of an attack profile's run, and 15 to 30\,\% of its attack actions fail because their preconditions are missing (e.g.\ exploit before scan port)
  \item Rerun with the baseline attacker's times in place of its tactic durations, same order of tactics: ASP rises from 0.09 to 0.45, against the baseline attacker's 0.66, closing 63\,\% of the gap
  \item The order of its tactics most likely accounts for the rest
  \item The rankings compare each attacker with its own NCR with no MTD, so the lower starting point is unlikely to decide which mechanism ranks first
\end{itemize}

\begin{frame}{Backup: the Petri net}
\begin{columns}[T]
\begin{column}{0.52\textwidth}
\centering
\includegraphics[width=\linewidth]{fig_4-3a_gspn_gadget}
\end{column}
\begin{column}{0.45\textwidth}
\small
Generalised stochastic Petri net \src{Ajmone Marsan 1995}, extended with the failure matrix $F$:
\[(P, T, I, O, W, M_0, F)\]
Base weight of the move from tactic $p$ to $q$:
\[W(t_{pq}) = \frac{n(p,q)}{\sum_{q'} n(p,q')}\]
with $n(p,q)$ the attack flows that draw $p \to q$. After a failed attack action:
\[W(t_{pq}\mid\text{failure}) = \frac{W(t_{pq})\,F(p,q)}{\sum_{q'} W(t_{pq'})\,F(p,q')}\]
One token, starting on Reconnaissance.
\end{column}
\end{columns}
\end{frame}
