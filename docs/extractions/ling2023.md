## Relevant artefacts

### The three-process TTC model (McQueen lineage) and its equations

**Source locator:** §Background "Time-To-Compromise"; §Method "Estimation of
TTC_ICS", Eqs (1)–(4), PDF pp. 4–5

**Paraphrase:** TTC_ICS adapts McQueen et al. 2006 ([`mcqueen2006`](mcqueen2006.md)).
An attacker is in one of two mutually exclusive processes — P1: a known
vulnerability *and* an available exploit exist; P2: known vulnerability, no
exploit — while P3 (find new vulnerabilities, build new exploits) always runs
in parallel. Four skill levels (novice / beginner / intermediate / expert);
higher skill ⇒ more usable exploits ⇒ lower TTC. Equations as printed:

- (1) `P1 = 1 − e^(−vm/k)`, `t1 = ((10/c2 + 3.9/c3)/2) days` — *v* = number of
  vulnerabilities for that component×attack type, *m* = exploits available at
  the skill level, *k* = 2740 (dataset total), *c2*/*c3* = mean CVSS v2/v3.
  `[parse-uncertain]` on the exact bracketing of the `/2` in t1 (printed as
  "((10∕c2 + 3, 9∕c3)2)"); the McQueen original should be checked for the
  intended form.
- (2) `P2 = e^(−vm/k) = 1 − P1`
- (3) `t3 = (f′ − 0.5) · b + t2` — *f′* = inverse of the exploitable fraction,
  *b* = mean-time-between-vulnerabilities (MTBV).
- (4) `T = t1·P1 + t2·(1−P1)(1−u) + t3·u·(1−P1)`, with `u = (1−f)^v`, `u = 1`
  if `v = 0`.

**Maps to:** [`../notes/2026-07-04_tactic_duration_precedent_survey.md`](../notes/2026-07-04_tactic_duration_precedent_survey.md)
§"The one per-technique yes" · [`mcqueen2006`](mcqueen2006.md)

**Disposition for this thesis:** contrasted — a *time-to-succeed* model priced
from vulnerability instances, not a per-tactic dwell; structurally inapplicable
to the substrate (no real CVEs), but the canonical demonstration of what
empirical technique-level timing requires.

### Provenance of every number (the crux for the gap argument)

**Source locator:** §Method "Estimation of TTC_ICS"; Table 4; §Background
"Vulnerability Dataset"

**Paraphrase:** every parameter's source is explicit — the model is empirical,
but each input is a *proxy with an admitted assumption*:

- **k = 2740** — the Thomas & Chothia ESORICS-2020 ICS vulnerability dataset
  (vs >185,000 in NVD); 8 main categories cover 95% of entries.
- **t2 = 37 / 27 / 16 / 6 days** (novice→expert) — derived by splitting the
  RAND exploit-development range (Ablon & Bogart 2017: developing an exploit
  for a known vulnerability takes 6–37 days, median 22) across the four skill
  levels. Admitted cross-domain assumption: "Even though the report is not ICS
  specific, we assume that the time that it takes to develop an exploit is the
  same for the ICS domain as for any other domain."
- **m** — Metasploit exploit count, with Metasploit's reliability *rank* used
  as the skill gate (rank "Excellent" usable by all four levels; rank "Low"
  expert-only).
- **f (Table 4)** — fraction of vulnerabilities exploitable per skill from the
  CVSS *exploitability* score: expert 0.1–3.9 → 1916 vulns, fraction 1;
  intermediate 0.1–3 `[parse-uncertain]` → 966, 0.50; beginner 0.1–2.1 → 455,
  0.24; novice 0.1–1.2 → 105, 0.05. Declared assumptions: only 1916 of 2740
  records carry the score (observed range 0.3–3.9) but the *theoretical*
  0.1–3.9 range is used; and CVSS-v2 entries lack an exploitability score, so
  the v2 *base* score substitutes — which explains the asymmetric numerators
  in t1 (v2 base max 10 → `10/c2`; v3 exploitability max 3.9 → `3.9/c3`).
- **b (MTBV)** — mean gap between ICS advisory creation dates per product-type
  × category; admitted proxy: "In reality the value shows how often a
  vulnerability is reported … but we use it as an indication of how often
  vulnerabilities are found."

**Disposition for this thesis:** verified [fetched] — the paper is the
strongest example that even the empirical frontier rests on declared
skill-splits and proxies; cite when defending Tier-3 declare-and-sweep as
continuous with, not weaker than, the field's "empirical" practice.

### Headline TTC values and the expert floor

**Source locator:** Table 7 (§Results); §Discussion first two paragraphs

**Paraphrase:** worked TTC_ICS values (days, novice / beginner / intermediate /
expert), for two assets × three vulnerability categories:

| Asset × category | TTC (nov/beg/int/exp, days) |
|---|---|
| HMI × Access control | 3594 / 98 / 15 / 6 |
| HMI × Information leakage | 2501 / 59 / 16 / 6 |
| HMI × Denial of service | 716 / 27 / 15 / 6 |
| Protection system × Access control | 5739 / 466 / 48 / 6 |
| Protection system × Information leakage | 37 / 27 / 16 / 6 † |
| Protection system × Denial of service | 5823 / 472 / 50 / 6 |

† MTBV = 0 artefact (all four vulns filed the same day); the Discussion's
correction with the category-average MTBV of 14 days gives 258 / 44 / 17 / 6.

The §Results technique lists are the bridge from these numbers to named
techniques (hence tactics): HMI×Access Control covers Manipulation of View,
Internet Accessible Device, Exploitation of Remote Services, Remote Services,
Lateral Tool Transfer; HMI×Info Leakage covers Data from Information
Repositories, Man in the Middle, Monitor Process State, Point & Tag
Identification, Screen Capture, Network Connection Enumeration, Remote System
Discovery; HMI×DoS covers Loss of View, Modify Alarm Settings, Service Stop;
Protection system×Access Control covers Program Upload, Change Operating Mode,
Internet Accessible Device, Program Download; Protection system×Info Leakage
covers Automated Collection, Monitor Process State, Remote System (Information)
Discovery; Protection system×DoS covers Alarm Suppression, Denial of Service,
Modify Alarm Settings. So e.g. Lateral Tool Transfer = 3594/98/15/6 and Screen
Capture = 2501/59/16/6 are usable per-technique rows.

The paper also states its own **relative ordering**: gaining access takes
longer than causing DoS or sniffing information ("It is expected that it would
take more time to gain access on an HMI compared to cause an DoS or even gain
information from, for example, sniffing") — access-gaining >
collection/discovery > service-impairment, independent of absolute scale.
Caveats that must travel with any quoted row: sample sizes are thin and
asymmetric (148 HMI vulns vs 32 protection-system); the higher
protection-system TTC is read as network-depth/OT-hardness (HMI at the edge,
protection system deep inside — the axis a stage-dwell model discretises); and
the numbers are **unvalidated** — "we are unable to compare it directly to
other existing TTC approaches", expert-interview validation is future work.

**Quote (the load-bearing observation):**
> "It is also noticeable from the results that regardless of the type of asset
> or category of vulnerability, an expert is able to compromise it in 6 days."

**Disposition for this thesis:** verified [fetched]. The 2501-novice / 6-expert
MITM-on-HMI pair quoted in the precedent survey is confirmed against the
primary source (Abstract + Table 7 row 2).

### Emergent idea — at expert skill the per-technique differentiation collapses

**Source locator:** Table 7 + Discussion (synthesis; the paper states the
observation but not the design consequence)

**Paraphrase:** the expert column is a constant 6 days across every asset ×
category — the value is pinned by the RAND exploit-development floor, and the
four-orders-of-magnitude spread lives entirely in the skill dimension, not the
technique dimension. Consequence for us: **under an APT (expert) assumption,
the field's best empirical per-technique method itself degenerates to a single
shared time** — empirical support for calibrating a small number of *group
anchors* rather than 15 per-tactic values, and for treating skill/actor class
(not technique identity) as the first-order timing variable. The Discussion
adds a second, skill-independent degeneracy: because many techniques share a
category×product mapping, "we will see the same TTC_ICS for many different
techniques … due to the lack of granularity" — even at novice level the
method's per-technique resolution is bounded by its category grain, which
tempers the "per-technique empirical yes" framing.

**Maps to:** [`../notes/2026-07-04_operational_validation_the_bar.md`](../notes/2026-07-04_operational_validation_the_bar.md)
§"Group, don't free-fit" · [`../tactic_profiles/README.md`](../tactic_profiles/README.md)
(five timing groups)

**Disposition for this thesis:** adopted-as-argument (our inference from their
data, flagged as such — the paper does not draw this conclusion).

### Which tactics have a CVE shape at all — and which structurally do not

**Source locator:** §Results paras 2–3; Appendix A (per-technique mapping
reasoning)

**Paraphrase:** the technique→vulnerability-category mapping gives each ICS
tactic a dominant *category shape*: Initial Access → Access Control / Web
(with exceptions: Supply Chain Compromise → Hidden Functionality); Execution &
Persistence → code/command injection (exceptions: Command-Line Interface →
Direct Shell Command, Hooking → DLL Hijacking; Valid Accounts → Default
Logins); Privilege Escalation → Authentication; Discovery & Collection →
Information Leakage (exception: Program Upload → Access Control); Lateral
Movement → Access Control (+ Default Credentials → Default Logins); Inhibit
Response Function (the ICS analogue of disabling defences) → predominantly
Denial of Service, but mixed (Manipulate I/O Image → Memory, Rootkit → Command
Injection, System Firmware → Code Injection); Impact → Loss of View → DoS,
Manipulation of View → Access Control. **Evasion is partially priceable, not
shapeless**: 4 of 6 techniques do categorise (Change Operating Mode → Access
Control, Masquerading → Control of Filename/Path, Rootkit → Command Injection,
Spoof Reporting Message → Cryptography). What remains **uncategorisable
because no vulnerability is exploited at all**: both Command-and-Control
techniques ("Using common ports … is not exploiting a vulnerability"),
Indicator Removal on Host ("removing or deleting traces of yourself … is not a
type of vulnerability"), Data Destruction, Activate Firmware Update Mode,
Exploitation for Evasion (any vuln), Spearphishing / Rogue Master / Removable
Media (unbounded vuln set). 13 of 78 techniques also drop out for lacking an
ICS asset (65 priced). Method notes: mapping is guided by MITRE's suggested
mitigations (mitigation "Access Management" → category "Access Control"), and
several of the shapes above land in the dataset's 21 manually selected
"Other" subcategories (Code/Command Injection, Direct Shell Command, DLL
Hijacking, Hidden Functionality, Control of Filename/Path) — thinner dataset
support than the eight main categories. Scope boundary: **ICS ATT&CK is 12
tactics** — Reconnaissance, Resource Development, Credential Access and
Exfiltration have no ICS counterpart, so this source contributes zero evidence
to those four profiles.

**Maps to:** profiles 13 (command-and-control), 07 (stealth), 08
(defense-impairment) — the "no CVE shape" finding is per-tactic gap evidence;
profiles 03/04/05/06/10/11/12/15 take the category-shape rows.

**Disposition for this thesis:** verified [fetched] — CVE-based empirical
timing *structurally cannot price* C&C and hiding-shaped verbs; those tactics'
dwells are free parameters in any model, which is exactly the Tier-3 territory
the catalogue declares and sweeps.

### Enterprise-IT transition anchors from the ethical-hacker survey

**Source locator:** §Discussion, final paragraph (citing Bromiley 2022,
SANS/Bishop Fox hacker survey [16])

**Paraphrase:** the majority of surveyed ethical hackers report they can
**break into an environment within 1–5 h of finding an exposure**, and
**collect data within 1–5 h of gaining access**. The authors use this to flag
the discrepancy with their 6-day expert TTC — possibly "typical IT systems are
faster to compromise" than ICS, or the two datasets' time scales are simply not
calibrated. Second-hand here (survey cited, not read): flag **[search]** until
the SANS/Bishop Fox report is fetched.

**Maps to:** profiles 03 (initial-access), 12 (collection) §4 rows — the only
hour-scale enterprise-IT transition anchors Step C surfaced from an academic
source; consistent in magnitude with the Sophos AAR milestone chain.

### Xiong disambiguation — two different "Xiong 2021"s

**Source locator:** §Related Work, para 3

**Paraphrase:** the enterprise-domain counterpart this paper contrasts itself
against is **Xiong, Hacks & Lagerström 2021, CSIMQ 26** ("A method for

characterisation, that method assigns TTC distributions by **systematic
literature review with per-source credibility ratings**, and its authors
