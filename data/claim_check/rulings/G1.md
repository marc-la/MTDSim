**Rule on Brown (item 3).** Brown §V-B describes MTDSim as breaking monotonic compromise: an MTD that disrupts an attack path revokes the attacker's control, which returns instantly once a path does. Zhang's version, which the code follows, never revokes it. The intent spec recorded this as disposition D-02. The sentence is true of the simulator you run and is supported by Zhang, but your supervisor co-wrote the version it departs from.

- **Recommended: leave it as item 3.** The section describes the simulator as run.
- **Alternatively, add one clause:** "… [zhang2023], unlike Brown's original [brown2023]". This costs words for a point no later argument uses.

**Considered, no change recommended.**

- **U0077 / U0091:** "no MTD mechanism changes [the exposed endpoints]" and the "internal" in Table 2.1's cells. These are true of the simulator as run. The exemption for mechanisms other than OS diversity is this repo's D-23 repair, and §6.5 discloses repairs generally. Citing `tay2024code` would be wrong, because the release exempts endpoints only from some mechanisms.
- **"So from 0 to 9 s" (item 5).** In today's code, an exploit the host's OS rules out costs 2.5× that time and is then refused. No reader-facing claim depends on it.
- **Two `tay2024code` citations in consecutive sentences (l. 979–982).** These are acceptable in IEEE style. Merging the sentences would be a rewrite.

**Net change: about 6 citations moved or added, and 0–1 clause, depending on item 1.**
